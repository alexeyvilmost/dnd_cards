# Локальная галерея звуков ElevenLabs

Студия для 70 промптов DnD Cards: четыре варианта на звук, прослушивание, выбор, редактирование промптов, перегенерация и история наборов. Выбор и аудиофайлы сохраняются локально. Это отдельный инструмент подготовки ассетов; привязка выбранных звуков к игре выполняется отдельно.

Выбранные 70 записей уже импортированы в игровой каталог; добавлены также 17 музыкальных тем. Устройство данных, настройки и команды повторного импорта описаны в [документации звука](../../../docs/combat-audio-v2-brief.md).

## Запуск через API

Из корня проекта в PowerShell:

```powershell
./scripts/start-audio-workbench.ps1 -Workflow api -Open
```

`api` — режим запуска по умолчанию. Галерея доступна по адресу [127.0.0.1:4317](http://127.0.0.1:4317). Скрипт запускает Node.js в фоне с двумя параллельными API-запросами; `-Concurrency 1` ограничивает генерацию одним запросом за раз. Допустимы значения 1 и 2. Для запуска в текущем терминале добавьте `-Foreground`, для другого порта — `-Port 4318`. Не нужны npm install, PostgreSQL или основной сайт. Требуется современный Node.js со встроенными `fetch` и `node:test`; рекомендуется Node.js 22+.

Сервер автоматически читает `ELEVENLABS_TOKEN` или `ELEVENLABS_API_KEY` сначала из окружения, затем из файла `.env` в корне проекта. Значения не выводятся в журнал и не возвращаются в браузер. Остальные параметры `.env` не загружаются в окружение процесса. Если ключ уже находится в `.env`, вводить его в галерее повторно не нужно.

Альтернативный способ — создать ключ в [Developers → API Keys](https://elevenlabs.io/app/developers/api-keys) с доступом к Sound Effects и вставить его в окно подключения на локальной странице. Введённый через страницу ключ хранится только в памяти до остановки сервера или отключения. При следующем запуске ключ из окружения или `.env` будет снова загружен. Ключ не нужно присылать в чат.

Загрузка галереи и чтение ключа сами по себе не отправляют платных запросов. Очередь запускается после команды генерации. В API-режиме кнопка «Создать недостающие» ставит в очередь показанные фильтром звуки, для которых ещё нет набора. Неудачные и прерванные варианты повторяются только отдельной явной кнопкой. «Перегенерировать 4 варианта» создаёт новый набор и сохраняет предыдущий.

Для прямого запуска:

```powershell
node scripts/audio/workbench/server.mjs --port 4317 --workflow api --data-dir outputs/audio-workbench
```

## Четыре варианта и стоимость

В [веб-интерфейсе ElevenLabs](https://elevenlabs.io/docs/eleven-creative/playground/sound-effects) одно нажатие Generate создаёт четыре варианта. [Публичный API Sound Effects](https://elevenlabs.io/docs/api-reference/text-to-sound-effects/convert) возвращает один аудиофайл на запрос. В API-режиме галерея делает четыре отдельных запроса на набор, соблюдая общий лимит параллельных запросов.

Запросы используют `eleven_text_to_sound_v2`, `loop: false`, `prompt_influence: 0.3` и MP3 44,1 кГц / 128 кбит/с. Длительность для API ограничена диапазоном 0,5–30 секунд. Для более коротких контактов запрашивается 0,5 секунды; желаемая исходная длительность сохраняется отдельно.

Полный первый проход: **70 × 4 = 280 запросов**, суммарная запрашиваемая длительность **195,6 секунды**. Галерея показывает объём запросов и аудио, но не оценивает расход кредитов. Стоимость определяется [тарифом ElevenLabs API](https://elevenlabs.io/pricing/api); тарифы веб-приложения отдельные. Если API возвращает `character-cost`, исходное значение сохраняется в метаданных ответа. Если такого заголовка нет, расход неизвестен, а не равен нулю.

Перегенерация и повтор ошибки отправляют новые запросы. После сетевого обрыва невозможно определить по локальному результату, выполнил ли ElevenLabs запрос и списал ли средства: галерея не повторяет его автоматически.

## Браузерный режим

Браузерный режим сохраняет запросы для выполнения Codex через открытую сессию ElevenLabs. API-ключ для него не нужен:

```powershell
./scripts/start-audio-workbench.ps1 -Workflow browser -Open
```

1. Войдите в [ElevenLabs Sound Effects](https://elevenlabs.io/app/sound-effects) в доступном Codex браузере.
2. В галерее нажмите «Заказать 4 варианта» или «Перегенерировать 4 варианта». Можно отфильтровать библиотеку и заказать недостающие звуки разом.
3. Попросите Codex в чате выполнить сохранённую очередь. Codex отправляет каждый промпт через интерфейс сайта, получает один набор из четырёх вариантов, скачивает четыре MP3-файла и добавляет их в галерею.
4. Слушайте готовые файлы и выбирайте вариант. Неудачный набор можно заказать повторно с изменённым промптом.

Галерея сама не управляет браузером. Статус «Ожидает генерации в браузере» означает сохранённое задание, ожидающее работы Codex. После завершения чата новые задания остаются в очереди до явного продолжения в чате. Перезапуск сервера сохраняет их; выбранные варианты также сохраняются.

Launcher создаёт `outputs/audio-workbench/downloads/` для импорта. Codex сначала копирует туда полученные браузерные загрузки. Свой каталог задаётся абсолютным путём к уже существующей папке:

```powershell
./scripts/start-audio-workbench.ps1 -Workflow browser -DownloadDirectory 'C:\AudioDownloads'
```

## Выбор, история и очередь

- Можно слушать готовые варианты, пока другие генерируются. Одновременно играет один предпросмотр.
- Выбор сохраняется сразу и переживает перезагрузку. Новый набор сохраняет историю и прежний выбранный файл, пока не выбран другой.
- Изменённые промпт и длительность применяются к следующему набору. Старые наборы сохраняют исходные параметры.
- В API-режиме пауза останавливает отправку следующих запросов; уже отправленный заканчивается и сохраняется.
- После перезапуска сервера API-очередь остаётся на паузе, незавершённый запрос отмечается прерванным. Готовые файлы не генерируются повторно.
- Ошибки доступа, недостатка средств и ограничения частоты приостанавливают API-очередь. После устранения причины можно продолжить её и явно повторить неудачный вариант.
- Экспорт скачивает JSON выбранных вариантов с локальными путями и параметрами генерации для подключения к игре.

Смена `-Workflow` или `-Concurrency` требует перезапуска сервера. Launcher проверяет режим, каталоги и число параллельных запросов уже работающего экземпляра. Для параллельной студии используйте другой порт **и отдельный каталог данных**.

## Файлы и параметры запуска

Каталог промптов: `scripts/audio/workbench/prompts.json`.

Данные по умолчанию находятся в `outputs/audio-workbench/` и исключены из Git:

- `state.json` — API-очередь, браузерные задания, наборы, снимки промптов и выбор;
- `audio/*.mp3` — полученные записи;
- `downloads/` — исходные браузерные загрузки для импорта;
- `server.stdout.log`, `server.stderr.log`, `server.pid` — файлы фонового запуска.

Launcher поддерживает `-Port`, `-DataDirectory`, `-Workflow api|browser`, `-Concurrency 1|2` (по умолчанию 2), `-DownloadDirectory`, `-Foreground` и `-Open`. Собственная папка скачивания должна существовать и задаваться абсолютным путём. Для прямого запуска сервер принимает `--port`, `--data-dir`, `--catalog`, `--workflow`, `--download-dir` и `--concurrency 1|2` (по умолчанию 1). Без явного `--workflow` прямой запуск сервера использует браузерный режим. Для переноса сохраняйте папку данных целиком.

Сервер слушает только `127.0.0.1`. Изменения требуют `X-Workbench-Token` текущей локальной сессии и проходят проверку источника. Ключ передаётся ElevenLabs локальным сервером; страница галереи напрямую к API ElevenLabs не обращается.

## Импорт браузерного набора

Для локальной интеграции Codex доступны следующие маршруты:

- `GET /api/state` — состояние галереи и текущий `csrfToken`;
- `POST /api/browser-request` — `{keys, requestId, prompt?, durationSeconds?}`; правки промпта допустимы для одного звука;
- `GET /api/browser-jobs` — незавершённые браузерные задания;
- `POST /api/import-batch` — `{key, requestId, files, jobId?, prompt?, durationSeconds?}`.

`files` содержит ровно четыре абсолютных пути к разным MP3-файлам внутри настроенного `--download-dir`. Проверяются реальные пути, формат MP3 и размер до 20 МБ каждого файла. При указанном `jobId` параметры должны совпадать с сохранённым заданием. Импорт копирует файлы в `audio/`, сохраняет новый набор и отмечает задание выполненным. Изменяющие запросы отправляются с `Content-Type: application/json` и `X-Workbench-Token`; один `requestId` сохраняется при повторе той же команды, чтобы не создать дубль.

## Локальная проверка

```powershell
node --test scripts/audio/workbench/server.test.mjs
```

Тесты используют подставной ответ провайдера и локальные файлы: они не обращаются к ElevenLabs и не расходуют кредиты. Реальные звуки появляются после запуска авторизованной генерации или импорта скачанного набора.
