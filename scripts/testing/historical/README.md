# Исторические входы миграций

`node scripts/testing/check-historical-fresh.mjs` создаёт отдельный локальный
PostgreSQL 17, запускает исходный `GetAllMigrations` и повторяет весь журнал.
Профиль `extended` вызывает его обязательным gate `historical-fresh-chain`.
Тест не читает `.env`, частный dump или папку `outputs` как источник данных.

Исторические миграции зависят от редактировавшегося вручную каталога. Поэтому
данные вводятся на явно проверенных границах: публичный bootstrap, исходные
версии механик, каталоги до 278/279 и поле источника 296. Это составленный
исторический тестовый профиль; он не утверждает, что обычный backend установит
всю историю на пустую production-БД без этих входов. Журнал миграций не засевается,
исходные guards не меняются, сертификаты автоматически не повышаются.

Значения берутся из проверенных публичных fixtures и Git blobs с закреплёнными
hashes. Три полных архивных preimage отзывов 102/103/119 хранятся отдельно в
`../fixtures/historical-revocations` и не являются действующими сертификатами.
Каждый адаптер проверяет границу, идентичность и предыдущие значения, сохраняет
остальные строки и журнал. Финал проверяет сами исходные отзывы, ручные статусы,
повтор всех таблиц, неизменность исходников и остановку принадлежащего тесту PG.

Для русского сопоставления классов используется built-in `C.UTF-8`:
plain `C` не приводит кириллицу к нижнему регистру. Явные SQL-пробы русского и
греческого текста входят в прогон. Возможность задания этой переносимой локали
описана в [PostgreSQL 17](https://www.postgresql.org/docs/17/sql-createdatabase.html).
