# Локальная проверка анимаций 2D, 29.09.2026

Сервис: `http://localhost:3001/`. Визуальная мастерская:
`http://localhost:3001/e2e/fixtures/combat-animations-preview.html`.
Мастерская использует обычный `TacticalBattleMap`, `CombatMapFeedback` и общий
декларативный каталог. Можно выбирать профиль, уровень 0–9, промах, ожидание
реакции, повтор; нажатие клетки переставляет цель только в этой сцене.

## Изолированная локальная среда

- Vite 3001 и PostgreSQL 5434 сохранены. API 8080 и worker 8090 запущены скрыто.
- База `combat_animation_286_20260929` — отдельная копия прежней
  `shop_review_249_20260915`, со всеми прежними аккаунтами и данными. Исходная
  база не мигрировалась. Перед копированием сохранён
  `outputs/combat-animation-286/before.dump`; это приватная резервная копия.
- Копия получила новую миграцию `286_combat_animation_metadata`: 70 профилей,
  58 назначений существующим здесь сущностям, все 35 заговоров и 8 атак укусом.
  Остальные декларации каталога предназначены для вариантов из более нового
  контентного снимка и отсутствующих сущностей здесь не создают.
- Обычный запуск нового API остановился на проверке прежней, не связанной с
  анимациями миграции `278_catalog_mechanics_audit`:
  `preimage drifted: ACT-feat-musician-song.name_en`. Она не была принудительно
  принята или отмечена выполненной. Новые контентные миграции 278–280 и
  последующие 281–285 остаются ожидающими.
- Для этого локального стенда `scripts/build-combat-animations-local.ps1`
  собирает Go API с overlay, который допускает только точное имя этой базы
  на loopback и выполняет только 286. Сохраняются блокировка мигратора, запись
  настоящей выполненной миграции и стандартные проверки запуска API. Порядок
  миграций в production-коде не изменён; этот бинарный файл не предназначен для
  выпуска на сервер.
- `scripts/start-combat-animations-local.ps1` запускает API; параметр
  `-Service worker` запускает worker. Прежние файлы worker сохранены как
  `outputs/combat-animation-286/before-*.{cjs,mjs}`, каталог архивных артефактов
  сохранён. Старые боевые снимки и artifact hashes не переписывались.

## Проверки

`scripts/roguelike/combat-animations-local.mjs` прошёл в установленном Chrome
против текущего Vite. Проверены все 70 профилей на каноничном поле, отсутствие
анимации исхода до завершения реакции, отсутствие попадания у промаха, рост
круга с 1 до 6 колец и радиуса 62→125, отсутствие перехвата указателя,
`prefers-reduced-motion`, ширина 390 px и совпадение центра SVG с источником.
Обнаруженная зависимость встроенного поля от стилей диалога исправлена прямым
импортом стилей в `CombatMapFeedback`; отдельное поле больше не смещает сетку
на клетку. Ошибок браузера и записей в API у мастерской нет.

Шесть кадров в `outputs/combat-animation-286/` проверены визуально:
`slash-desktop.png`, `bite-desktop.png`, `fire-desktop.png`,
`frost-level9-desktop.png`, `hide-desktop.png`, `frost-mobile.png`.
Снимки сделаны на 32% объявленной длительности, без изменения игровых данных.
Машиночитаемые результаты: `browser-evidence.json`.

Финальный адресный Vitest-прогон: 90 passed, один ранее существующий skip,
10 файлов (рендерер, профили, очередь, журнал, обычная/3D-страница, аудио и
политика подсказок). Дополнительно прошли реальные сценарии «Пляшущих огоньков»
и «Малой иллюзии»: координата эффекта сохраняется в новой записи журнала,
предшествующая история остаётся неизменной. TypeScript, Vite и проверки
целостности ресурсов DiceBox также выполнены.

Диагностический расширенный `soloCombat.engine.integration` выявил 28 старых
падений из 298 тестов; отдельный запуск исходных HEAD-версий `engine.ts` и
`combatLog.ts` воспроизвёл те же 28 имён падений (270 passed). Этот общий набор
не объявляется зелёным и его прежние механические ошибки здесь не исправлялись.

`scripts/roguelike/combat-animations-live-local.mjs` создал отдельный QA-аккаунт,
личную копию штатного пресета и новый забег. Реальная последовательность
`start_encounter` → `initialize_combat` → действие «Рывок» прошла через API и
авторитетный worker. Финальный прогон нажал обычную кнопку «Рывок» в хотбаре
настоящего 2D боя и проверил появившийся `action.dash` на поле; кадр сохранён
в `live-dash-animation.png`. Новый сохранённый журнал преобразован каноничным
`presentCombatEntries` в профиль `action.dash`. Повтор каждой команды возвращал
исходный ответ. Реальный экран 2D боя открылся и сохранил ревизию после
перезагрузки. Здоровье, ресурсы, случайность и исход не подменялись.

В том же прогоне каталог анимаций вернул 200 реальному пользователю,
401 без авторизации и 403 на изменение назначения обычным пользователем.
`live-evidence.json` и `live-combat-desktop.png` содержат результаты;
`credentials.json` и `live-run.json` — приватные локальные QA-артефакты.

Финальная сборка API включает отказ от ложного rollback 286; worker собран
после последних изменений engine. Оба health endpoint возвращают `ok`.
Артефакт worker:
`sha256:7192155f01fd032c3d93986499a16c5e0a09c8eba44b50b2bd917246ca09348d`.

Это проверка отображения и одного настоящего действия, не утверждение о
полном прохождении всех заклинаний в естественном бою. Коммит, push и TimeWeb
не выполнялись.
