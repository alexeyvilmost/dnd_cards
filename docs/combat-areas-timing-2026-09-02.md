Самый длинный суммарный расход — release/browser feedback loop: три успешные выкладки, одна автоматически откатившаяся попытка и два production-only исправления заняли около 39 минут от первой выкладки до финальной сертификации. Реальные пользовательские проверки после готового релиза заняли примерно 7 минут.

## Как ускорить следующие изменения

1. Сохранить профильный тестовый набор областей как отдельную короткую команду; запускать его после каждого изменения, а production-сборку — один раз перед release.
2. Вынести JSON-схему `world_zone.tactical` в общий тип и валидатор backend/frontend. Это уберёт ручную проверку названий `triggers`, `inside_condition`, `on_failure`.
3. Добавить небольшой каталог эталонных площадных сценариев (постоянная опасность, временная труднопроходимая зона, концентрационный туман, сигнализация). Тогда новая сущность проверяется данными, без отдельного интеграционного теста.
4. Добавить в конструктор сущностей предварительный просмотр клеток и симуляцию события входа. Это перенесёт большую часть ручной отладки до выкладки.
5. Не запускать старые длинные сценарные pipeline для локальных изменений этой подсистемы. В этом прогоне использованы только типизация, backend-тесты, 57 профильных тестов и одна release-сборка.
6. Добавить PostgreSQL-интеграционный smoke для миграций, использующих повторный placeholder в колонках разных типов. Он поймал бы ошибку `$2` до семиминутного server build/rollback.
7. В тестах площадных действий всегда использовать production-shaped ID (`uuid@CLASS-…`), а не короткий `grease`. Это убирает отдельную выкладку ради расхождения валидатора.
8. После deployment открывать новый PWA-tab, а не перезагружать старый. Старый service worker дважды создавал ложное впечатление, что исправление не сработало.
9. Не повторять локальный production build перед каждым маленьким follow-up: профильные тесты + `tsc`, затем единственная обязательная сборка runner на Timecloud. В этом проходе такой подход сэкономил одну дополнительную минутную локальную сборку на втором исправлении.
