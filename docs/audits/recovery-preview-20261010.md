## Найденная причина и исправление интерфейса

Превью действия читало только `actions.recharge`, пропуская `mechanics.uses.per` и явную политику `mechanics.uses.recovery`. Поэтому сроки отсутствовали даже у полностью объявленных пулов. В режиме игрока техническое описание механики скрыто и не компенсировало этот пропуск.

Каноничные превью действий, заклинаний и активируемых эффектов теперь используют общий форматтер восстановления. Он различает полное, фиксированное и случайное восстановление. Информация находится в блоке метаданных с иконкой восстановления, рядом с компактным счётчиком использований. Детальное превью действия использует тот же форматтер. Срок не выводится из имени или UUID сущности; описание не парсится при показе превью.

Собственный пул объявлен у **54 действий**. У 53 не было корректной отдельной подписи; у «Целебных рук» она уже была. Для общих ресурсов использованы объявления ресурсов класса, эффекты предоставления/восстановления, описания ресурсов и исходных предметов.

Из остальных 230 действий: 206 не имеют отдельного ограниченного пула, 10 уже имеют заполненную подпись восстановления, 10 расходуют ячейки, одно — кость хитов, два — сам предмет, одно — «Целебные руки» с корректной существующей подписью. Повторный отдых не представлен как восстановление одноразовых предметов.

Примеры:

- «Небесное откровение» и его варианты, дыхание драконорождённого, «Драконий полёт»: долгий отдых.
- «Всплеск действий»: короткий или долгий отдых.
- «Второе дыхание» и «Тактический ум»: короткий отдых возвращает один заряд, долгий — все.
- Божественный канал, Дикий облик, ярость, псионические кости: сохранена частичная политика короткого отдыха.
- Вдохновение барда: указан переход к восстановлению коротким отдыхом с 5-го уровня.
- «Дикое возрождение: ячейка» и «Оглушающий удар»: перечислены разные сроки их собственных и общих ограничений.
- Дозы яда, угощения, огненное дыхание зелья, комплект целителя: описано получение нового запаса, а не выдуманное восстановление отдыхом.
- «Мгновение»: боевой переброс ограничен разом за ход; короткий отдых из описания относится к отдельному внебоевому свойству предмета и не перенесён на переброс.

## Заклинания

Ни у одного из 511 заклинаний не объявлен собственный `mechanics.uses`. Обычным заклинаниям не добавлена одинаковая перезарядка: они расходуют ячейки, восстановление которых зависит от источника магии и способностей персонажа.

«Удар Афины» уже содержит ограничение до короткого отдыха в описании. Его механика намеренно отсутствует по предыдущему запросу пользователя; пул зарядов этой миграцией не создаётся. «Молебен лечения» ограничивает повторное получение преимуществ **получателем** до его долгого отдыха — это не перезарядка заклинания. Тексты этих двух заклинаний сохранены. Если заклинанию будет явно задан собственный пул, общий форматтер уже отобразит его восстановление.

## Выявленные расхождения, сохранённые для отдельной работы над механикой

- Три действия «Сапог уворота»: текст предмета говорит о `1к6` на рассвете, действующая bounded-политика — о `1к6` после долгого отдыха. Превью показывает объявленную исполняемую политику, не обещая полное восстановление. Переход к календарным событиям не выполнен этой миграцией метаданных.
- Девять вариантов «Амулета восстановления»: описание говорит о ежедневном использовании, ресурс исполняется через долгий отдых. В подписи явно сохранены оба условия.
- Получение угощений и доз яда имеет дополнительные условия изготовления. Подпись отражает исходное описание; миграция не создаёт новый механизм производства расходников.

## Применение и защита данных

Это самостоятельная SQL-миграция, не зарегистрированная для автоматического запуска сервиса. Применять её при явном запросе на релиз вместе с обновлением интерфейса. Перед применением использовать свежий резервный снимок БД.

Миграция выполняется одной транзакцией с ограничением времени ожидания блокировок. Она блокирует и проверяет 47 источников политик, сверяет идентичность, механику, описание и прежние метаданные каждой исправляемой сущности. При расхождении останавливается целиком: требуется повторный аудит изменившейся записи, а не обход проверки. Изменение только статуса проверки или картинки не блокирует миграцию.

Из 47 источников 45 дополнительно сверены со свежим публичным API прода — различий в используемых полях нет. Два исходных предмета («Амулет восстановления» и «Сапоги уворота») не доступны через публичный API без авторизации; их данные взяты из локального снимка и остаются под обязательной проверкой отпечатка непосредственно при применении SQL.

Меняются исключительно `actions.recharge`, `actions.recharge_custom` и обычная отметка времени обновления. Статусы проверки сохраняются несмотря на старый триггер инвалидации. Исполняемые механики, ресурсы персонажей, инвентарь, сохранённые бои и история не изменяются. Повторный запуск не меняет даже время обновления уже исправленных записей.
