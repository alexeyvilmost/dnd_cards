# CI21 и ожидание загрузки правил в тесте

В [CI21 исходника `197fd282`](https://github.com/alexeyvilmost/dnd_cards/actions/runs/37408881509) все 944 проверки Node прошли. Набор unit остановился в `App.rules-lab.test.ts:97`: тест обычного маршрута проверял вызов API после одного прохода таймера, хотя компонент проверки правил загружается асинхронно. Backend и основные пользовательские сценарии прошли; частичные результаты не разрешают публикацию или выкатку.

Тест теперь управляемо задерживает настоящий ленивый импорт. До его завершения он проверяет отсутствие вызова API и недоступность игрового экрана, затем отпускает импорт и ждёт фактического начала проверки правил. Проверки точных параметров версии правил и запрета взаимодействий до принятия правил сохранены. Все 21 случая файла, проверка типов, lint и production build прошли локально. Приложение и правила этим исправлением не меняются; требуется новый точный CI.

Отдельный локальный опыт проверил удаление повторных запросов одной сущности внутри одной порции потребностей движка. В исходник сервиса это изменение пока не включено. На реальном интерфейсе приняты 96 боёв, из них 80 измеряемых, по 20 на вариант и размер группы. Для одного персонажа медиана 307,8→302,9 мс, для шести — 733,3→652,3 мс. Для шести потребности каталога сократились 150→25, операции SQL — 183→58. p95 предварительный: 985,1→943,1 мс. Следующий шаг — более длинная независимая серия, а не включение по одному измерению.

Семь проверок БД и настоящего worker прошли без пропусков, включая одинаковые входы и seed для групп 1/2/6 при инициализации, отдыхе, изменении инвентаря и ходе лагеря. Два варианта используют отдельные явно зафиксированные Go binaries, одну тестовую БД, worker и UI; batch, mirrors, cache, сжатие и очередь выключены. Повторы, reload, неизменность исходных листов и остановка стенда подтверждены. Эти результаты относятся к локальным публичным данным; исходные отказы подготовки сохранены отдельно.
