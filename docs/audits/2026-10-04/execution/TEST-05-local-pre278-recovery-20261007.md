# Локальное восстановление исходных данных перед миграцией 278

По разрешению владельца проверены сохранившиеся файлы на этом компьютере. Найден подлинный продовый дамп от 28 сентября с исходной границей 272. После выполнения неизменённых миграций 273–277 прошли 1653 из 1656 предусловий миграции 278. Три оставшихся условия доведены до точного совпадения только значениями из проверенных исторических источников. Исходные manifests, UUID и guards не менялись.

Составленный источник покрывает 1605 условий существующих сущностей, соответствующих 1575 различным сущностям. Это явно составленный набор, а не найденный полный оригинальный каталог от 29 сентября. Для FEAT-0075 неизменённый текст подтверждён своим hash в оригинальном дампе, а прежний related_effects получен из подлинного before_fields архива миграции 278; ожидаемый manifest используется только для проверки.

На отдельном PostgreSQL 17.11 все 1656 предусловий прошли, исходная миграция 278 применена и повторена. Повтор сохранил полные хэши строк всех таблиц; существующие таблицы вне каталога сохранили полные хэши; при восстановлении каталога личные строки не импортировались. Созданные самой миграцией публичные audit-таблицы проверяются отдельно. Все принадлежащие прогону ресурсы остановлены.

Исправлена совместимость обезличенного импортёра со старыми схемами: он проверяет все реально существующие таблицы вне разрешённого каталога, включая V1/V2, и не требует таблиц, появившихся позже. Семь тестов прошли без пропусков. В восьми реальных старых снимках проверка дополнительно отказала при внесении одной строки в новую произвольную таблицу вне каталога.

Неудачные попытки сохранены. Проверка на старом локальном снимке правильно отказала при отличающихся UUID; проверка после выполнения миграций была уточнена для созданных ими публичных audit-строк без ослабления проверки личных входных данных.

Полная историческая установка с пустой схемы пока не доказана: текущая проверка начинается с подлинного каталожного baseline 272. Требуется включить эти источники в полный прогон и отдельно проверить миграционно созданные идентичности. Прод не менялся. Тест не присваивал ручные статусы; исходные операции миграций выполнялись без изменений. [Машинная запись](TEST-05-local-pre278-recovery-20261007.json).
