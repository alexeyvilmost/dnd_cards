# PERF-04 — загрузка экранов и страницы библиотеки

## Реализовано локально

Тяжёлое отображение Choice/Dice вынесено в ленивые hosts. Контексты сохраняют API и время жизни запросов; Cancel доступен во время загрузки и ошибки chunk. Размонтирование завершает ожидающий запрос отменой, поздний chunk не выполняет действие и не бросает кубики. ChoiceResolver перенесён без смены каноничных компонентов; старые exports сохранены для совместимости.

Проверка серверных правил перенесена в отдельную границу игровых маршрутов. Библиотека, вход и настройки не загружают боевую зависимость. Экран игры появляется только после database_release; offline fixture показывает состояние недоступности и повтор подключения. Недоступные правила не разрешают команду. Paper sheet и изолированный RulesLab сохраняют свои границы.

11 каталогов поддерживают review_status и review_summary. Сводка вычисляется после существующих permission/search/tag/type predicates и до фильтра статуса/пагинации. SQL использует COUNT(DISTINCT id); нормализация восьми статусов совпадает с каноничной UI-функцией, сохранённые старые статусы не переписываются. Без новых параметров response совместим со старым клиентом. Ресурсы, переменные и понятия получают серверный поиск и страницы по50 в библиотеке; старые вызовы без page/limit сохраняют прежний контракт.

CardLibrary получает только запрошенную страницу, а счётчики — из сводки. Смена фильтра/аккаунта/статуса отменяет принятие устаревшего ответа. Review-запросы обходят TTL, но сохраняют проверку текущего аккаунта. Отсутствующую сводку старого сервера UI явно считает ошибкой; число загруженных элементов не выдаётся за число каталога. При раздельной выкатке сначала требуется backend с этим additive контрактом, затем frontend.
