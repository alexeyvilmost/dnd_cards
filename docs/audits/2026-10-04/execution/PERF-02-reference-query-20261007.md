# Чтение карточек и смена экипировки — 7 октября

Причина задержки установлена на локальной БД: обогащение карточек обратными ссылками вызывало каноничный resolver для несвязанных записей всего каталога. Сам запрос доступа к карточке выполнялся менее миллисекунды. EXPLAIN 72 запросов показал 245–280 мс на прежнее обогащение и 0,18–3,69 мс после ограничения исходных кандидатов; результаты по количеству строк совпали для четырёх карточек. Отдельный HTTP-тест сравнил полные строки и подтвердил прежние права, видимость, уровни, typed/wildcard/hinted ссылки и stable aliases. Проверена и актуальная версия resolver284.

Для каждого режима выполнены 124 настоящие операции браузера, включая четыре прогрева; по 30 измерений на сценарий. Сборки UI, движка и fixtures одинаковы, новый backend имеет явную привязку к локально изменённому исходнику. Ревизии, размещение и ёмкость ресурса проверены; исходные персонажи неизменны, ошибок браузера нет, временные процессы завершены. Это локальные последовательные серии, не скорость продового OCI.

Готовится включение серверной подготовки экипировки. Для предмета с ресурсом удержание блокировки сокращается примерно с 52 мс медианы до 8 мс; p95 — примерно с 64–70 до 9 мс. Обычный предмет через оптимизированный прежний endpoint быстрее: около 41 мс против 95 мс медианы intent. Выбор intent опирается на авторитетную серверную подготовку и короткую запись без worker/HTTP под блокировками; преимущества по всем задержкам относительно уже оптимизированного старого пути нет.

Семь обязательных тестов с подслучаями прошли без пропусков: конкуренция, изменение прав/владения/каталога/фазы, подготовка без блокировки строки и ровно одно применение. Принятая команда читается при повторе даже после выключения intent; откат приложения использует сохранённую конфигурацию и не восстанавливает старую БД. Настоящий Docker Compose подтвердил единственное изменение эффективной конфигурации — equipment intent OFF→ON.

Исправление и конфигурация пока локальны; текущая выкатка 05085 их не содержит. Следующий выпуск должен пройти обычные CI, публикацию, свежую резервную копию и проверку кандидата, затем сверку живой конфигурации. Предыдущие отчёты сохранены как история измерений.
