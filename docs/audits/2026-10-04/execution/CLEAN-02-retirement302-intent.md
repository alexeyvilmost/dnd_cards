# CLEAN-02: сохранение запроса до явного удаления302

До запуска отдельной команды теперь можно сохранить исходный запрос, прежнее состояние, точный исполнитель и хеш одобрения в общем журнале. Перед отправкой команды сохраняется неопределённый исход; потеря ответа не разрешает другой запрос или обычную выкатку. Подтверждённый результат переводит ту же запись в формат2 с полным исходным intent. Старые записи формата1 не переписываются.

178 проверок прошли на Windows и на реальном Linux-образе без сети и с источниками только для чтения. Из15 новых проверок две завершают настоящий дочерний процесс сразу после атомарной записи: запрос и фаза сохраняются после аварии, оставшийся lock блокирует новый процесс. Его удаление выполняется только в тесте для известного уже завершённого дочернего процесса; автоматическое снятие production-lock не добавлено. Контейнер проверки удалён, контрольные суммы источников совпадают.

Это локальная проверка метаданных и файловой системы. КомандуSQL этот модуль не вызывает; интеграция host-исполнителя и свежая production-проверка остаются отдельным этапом. Текущую выкатку a0c4db75 эта подготовка не задерживает.

Интеграционная проверка формата2 подтверждает сохранение полного исходного запроса в публичной проекции и baseline следующей сборки. Утрата intent, приватные поля и подмена одобрения отклоняются даже после пересчёта внешних хешей. Текущий набор179 проверок прошёл на Windows; все6 проверок проекции и её настоящегоCLI прошли наLinux без сети. Это дополнение к прежнему отдельному прогону178, а не переаттестация старогоLinux-отчёта. Исполняемый код не изменён.
