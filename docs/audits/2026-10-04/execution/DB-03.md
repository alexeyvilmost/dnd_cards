# DB-03 — закреплённые каталоги и холодные поля забега

Статус: `implemented_local_correctness_verified; latency_gate_failed_default_off`.
Повторная проверка на 100 согласованных парах из одной восстановленной БД
не закрыла latency acceptance: init p95 141,07 → 149,22 мс (+5,78%),
95% bootstrap интервал отношения [1,0101; 1,1407]. Writer остаётся OFF.
После узкого переиспользования внутри транзакции SQL уменьшены 29→27 / 17→16,
но повторные 100 пар снова дали отрицательную latency acceptance: init p95
138,48→147,12 мс (+6,24%). Настройка остановлена, код заморожен для общего набора.
[Исправление, тесты и окончательное решение](DB-03-transaction-scope.md).
Новая серия и её ограничения: [DB-03-latency100.md](DB-03-latency100.md).
Ниже сохранена предыдущая серия из 30 примеров; её числа не переписаны.
Writer выключен (`DB_FROZEN_CATALOGS=0`). Production migration/настройки/перенос
истории не выполнялись. Это ограниченный первый этап DB-03: hot CharacterV3,
динамический envelope и боевой журнал сохраняют прежнее представление.

30 настоящих новых боёв с одним владельцем использовали один и тот же frozen
input (один distinct JSON). Additive migration 299 добавляет owner-scoped
immutable table и nullable FK. Hash включает целиком исходный каталог, owner,
artifact hash, protocol и serializer `go-json-v1`. Совпадение hash после INSERT
проверяется чтением сохранённого payload; foreign owner/missing/corrupt/version
ошибка блокирует команду, fallback к изменившейся библиотеке отсутствует.

Pin вызывается только для нового `initialize_combat` в прежней транзакции
run/character/journal/receipt. Старые inline catalogs/артефакты не переносятся.
Чтение восстанавливает тот же приватный frozen input; HTTP/worker envelope,
исторические baseline/hash и frontend contract не менялись. `state.catalogActions`
**динамический** (вызовы/предметные действия меняют его), поэтому он не объявлен
неизменяемым и не вынесен в статический кеш. В save исключаются неизменившиеся
catalog/checkpoint/shop/mode_rules; изменённые nested values сохраняются.

Rollback: выключить новые pins; **сохранить** reader, таблицу, FK и migration.
Старый бинарник без reader не пригоден после появления ссылок. Down отказывает.
Удаление unused catalog не реализовано: старый каталог может быть нужен истории,
rollback/backup. Append-only trigger остаётся включённым.

параллельная CPU нагрузка дают только диагностику: **init p95 не улучшился**,
критерий отсутствия регрессии не закрыт. До включения нужен спокойный ≥100 samples
gate, либо оптимизация повторных проверок с сохранением integrity/privacy.
