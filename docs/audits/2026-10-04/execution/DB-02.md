# DB-02 — точные сжатые квитанции

Статус: `implemented_local_verified; awaiting_common_core_and_production_decision`.
Новый writer выключен по умолчанию (`DB_COMPACT_RECEIPTS=0`). Внешние настройки,
production migration/backfill, TTL, очистка истории не выполнялись.

DB-01 подтвердил рост receipts около 44 MB на 1000 настоящих camp_turn. Добавлены
version 2 (gzip JSON bytes + SHA-256 + исходная длина) и additive migration 298
для двух существующих ledger. Identity/request fingerprint/type/ruleset остаются
в прежних колонках, состояние/события/receipt коммитятся прежней транзакцией.
Прежний JSONB не переписывается. Маленькие/невыгодно сжимаемые ответы остаются v1.
Reader проверяет границы, целостность, версию и точный снимок; актуальное состояние
персонажа для реконструкции не используется. Ошибка чтения не запускает повтор
команды. Внутренние storage поля исключены из публичного JSON.

Rollback: выключить **writer**, сохранить dual reader и additive schema. Откат
на старый бинарник без v2 reader после появления v2 недопустим. Down отказывает.
Backup inventory декодирует v2 постранично, проверяет hash/length и обходит старые
artifact/media references; отсутствие/повреждение блока не маскируется пустым
результатом. Сжатые ledger не исключены из retention protection.

## Реальные локальные проверки

`node scripts/database/compact-receipts-drill.mjs --output <new report>`:
1000 настоящих camp_turn через API/worker/PostgreSQL, 1000 точных retries, затем
1000 **тех же ответов** записаны в отдельную owned shadow таблицу как legacy JSONB
с теми же индексами. Исходные receipts не обновлялись. PostgreSQL TOAST уже учтён:

| Представление тех же 1000 ответов | Relation bytes | TOAST + index bytes |
|---|---:|---:|
| Legacy JSONB shadow | 44,507,136 | 44,023,808 |
| v2 реальный ledger | 26,492,928 | 25,968,640 |

Уменьшение relation — **40.47%** на этой синтетической нагрузке. Исходный JSON
94,323,147 B, gzip 24,522,644 B; это логические размеры, их нельзя складывать с
physical relation. Средняя обработка encode — 1.47 ms. Ускорение API не заявлено:
отдельного сопоставимого legacy latency прогона не было, параллельно шли сборки.
Таблица shadow отражает одинаковые ответы, а не «похожий» другой RNG прогон.
Полный безопасный результат: `DB-02-storage.json`, cleanup `stopped`.

`restore-drill.mjs --compact-receipts 1`: полный snapshot/restore нового v2 ledger,
pending paid influence, exact prior response и duplicate после restart; target
**выключает** compact writer и всё равно читает v2. Семь проверок PASS, оба стенда
stopped. Nonempty media references не потерялись. `DB-02-recovery.json`.

Owned DB-only Go: `TestReceiptStorage*|TestCompactReceipt*` — **6 top-level PASS**,
0 skips, включая реальные миграционные constraints/idempotency/history,
concurrent retry, mismatch, rollback при receipt/journal failure и отключение
writer. Run `test_09f390989baf412b6a387e20`; cleanup stopped. Node codec/backup
tests — **6/6 PASS**. SQL observers/хеши не подменяют сохранённый результат.

Ограничения: production объём/нагрузка не измерены; v2 экономит место, но добавляет
CPU на encode/decode. Самостоятельный process-kill посреди transaction не исполнен;
rollback доказан реальными SQL транзакциями/ошибками, recovery — restart/restore.
Общий core/extended интеграционный gate проводится владельцем плана отдельно.
