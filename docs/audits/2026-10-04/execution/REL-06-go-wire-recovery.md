# Воспроизведение истории и следующая выкатка

Исправлена причина расхождений в локально сохранённой истории: PostgreSQL JSONB меняет порядок ключей объектов, а старые версии движка в некоторых расчётах используют этот порядок. Сервер передавал объекты через Go JSONMap; теперь чтение истории явно восстанавливает тот же порядок на каждом входе движка. Массивы, кубики, сохранённые результаты и старые исполняемые файлы не изменяются. Прямые вызовы worker сохраняют прежний режим.

На защищённом оригинальном снимке первой попытки прошли все **136 боёв, 2344 записи и 2209 команд**, использующие 18 исторических движков. Это именно снимок 2026-10-05T06:35:01.822Z, а не третий capture или текущая БД. Первоначальные112/24расхождения сохранены в [записи третьей попытки](CI-11-third-rehearsal.md). Отдельный первый диагностический wrapper отказал из-за неверного предположения о baseline; его квитанция сохранена, исправленная проверка учитывает обе формы baseline.

Объединённый исходник прошёл33 локальных Node-проверки, включая настоящий Go encoder и HTTP worker, и27 Linux-проверок восстановления выкатки; пропусков нет. Проверены два разных набора данных, все шаги, сохранение входов, отказ при подмене хеша, RNG, схемы, порядка/пропуске команд. Все4424 входных файла сохранили байты во время проверки; временный Linux container удалён. Отдельная проверка курсора19/19подтвердила полный UTF-8 поток без сохранения SQL-результатов в Docker logs. Ускорение этой правки не измерено.

Новый trusted proof связывает все три реальные failed deploy attempts, полные отчёты, исходные здоровые компоненты, отсутствие cutover/journal/lock и завершённую очистку. Он разрешает только обычную новую ручную попытку со свежим capture; успешной репетицией прежний отказ не становится. Старые proof bytes сохранены.
