# TEST-05: изолированные части основного и расширенного набора

Runner поддерживает `--shard unit|backend|flows|extended`: core использует первые три, extended — все четыре, а сокращённая component selection исключает только действительно пустые части. `suiteWorkload` формирует единственный перечень Node/Vitest файлов, Go packages, API/browser групп, обязательных gates и UI fixture profiles. Каждая единица имеет ровно одного владельца; обязательный Go extended selector по-прежнему перечисляет все пакеты и все неархивные тесты, а dedicated cases направляет в обязательные gates.

Локальный запуск: `node scripts/testing/run-shards.mjs --suite extended --full --output outputs/testing/extended-sharded`. Orchestrator одновременно выполняет не более двух частей, каждая использует собственный registry, PostgreSQL, порты, binary, worker build и UI build. Vite получает явный `--config vite.config.ts`, чтобы старый ignored скомпилированный `.js` не подменил конфиг; PWA читает manifest фактически выбранного outDir. TypeScript работает без общей записи tsbuildinfo. Worker tests проверяют свою owned distribution, а не shared `frontend/worker/dist`.

CI использует ту же выборку, matrix max-parallel2 и отдельные receipts. Единственный release-eligible artifact `local-suite-results` появляется после строгого aggregate: все части присутствуют один раз, завершились без skip/retry/cleanup failures, содержат одинаковые source/manifest/lockfiles/selection, worker/UI bytes. Aggregate заново вычисляет требуемый workload по checkout и сверяет полные source snapshots/catalogs. Часть набора не может авторизовать release. Продолжительность отчёта — реальный span earliest start→latest finish; max duration отдельной части сохраняется отдельно и не выдаётся за ускорение всего набора.
