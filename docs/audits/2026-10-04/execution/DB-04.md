`retention-plan.mjs` теперь хранит prepared identity и результат в отдельном
owned-test ledger атомарно с удалением/восстановлением индекса. Повтор после
потерянного подтверждения возвращает `already_applied`/`already_restored`, без
повторного DDL и без второй записи. Изменённые export, оставшийся индекс,
предварительный снимок или DB ownership блокируют операцию. EXPLAIN ANALYZE
до/после подтвердил прежние строки, тип узла, стоимость и использование
сохранённого индекса. Время маленького fixture записано как диагностика;
его нельзя выдавать за production latency.

Новый `scripts/database/inline-image-export.mjs` экспортирует только явно
указанное изображение владельца из owned local DB, проверяет точные bytes/hash
и восстанавливает прежнюю data URL в приватный локальный файл. Проверены
повторный export/restore, неизменность entity, повреждение blob, изменение
владельца/reference и потеря DB marker. В положительном тесте — настоящий
минимальный GIF. Внешний storage и ссылки в БД инструмент не меняет.

Прежние результаты ниже сохраняются как история проверок.
Никакой production query, scheduler, изменения storage, удаления пользовательских

`retention-plan.mjs` создаёт консервативную matrix: user characters/runs/documents/
images, receipts/journals, frozen catalogs и все artifact/history/pending/backup/
rollback references сохраняются. Неиспользуемая вкладка, старый timestamp,
soft-delete и zero scans не являются разрешением физического удаления.

Executable local scope — один exact duplicate valid/ready nonunique simple btree,
без constraints/dependants/replica/partial/expression/include. Сверяются реальные
ключи, порядок/options, opclasses/collations, tablespace/storage settings и
семантика определения. Такой duplicate имеет доказательство независимо от
нулевого счётчика; остальные индексы требуют query-window/EXPLAIN/владельца.
Более сложный DDL, который адаптер не умеет точно восстановить, исключён.

Apply возможен только через явный candidate ID в том же runner-owned loopback
PostgreSQL, после registry+DSN+DB marker. План связан hash/run ID/preimages;
recovery export записывается до изменения. Проверка prepared identity и
определений под lock в transaction отвергают stale plan. Restore принимает только
этот owned export и строгий CREATE INDEX; широкого SQL executor/force нет.
Никакого удаления rows, receipts или каталогов этот applicator не поддерживает.

## Ограничения и дальнейшие решения

Внешний storage перенос data URLs, lifecycle удаления владельцем, retention
старых snapshots/CJS/media и production index changes требуют отдельного
конкретного плана/доступа. Подтверждённого production query window нет; адресной
production migration удаления индекса не создано. Ordinary VACUUM — повторное
использование места, не обещание уменьшения файлов ОС; VACUUM FULL не запускался.
Матрица и воспроизводимые команды находятся в `docs/database-storage.md`.
