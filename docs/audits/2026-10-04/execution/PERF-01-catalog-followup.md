# PERF-01/02/04 — замыкание зависимостей и актуальность каталога

Локальная адресная приёмка прошла; общий финальный набор выполняется отдельно. Старые измерения не переписаны.

* Горячие пути листа, отдыха, добавления участника и bootstrap больше не перечисляют весь каталог предметов. `/api/cards/runtime/resolve` возвращает до 128 запрошенных UUID, заново проверяет itemAccessQuery и отказывает всему запросу при недоступном элементе. Каноничный loader раскрывает вложенные контейнеры волнами, с дедупликацией и пределом 4096 сущностей. Старые серверы имеют fallback по detail endpoints только при нетипизированном 404 отсутствующего маршрута.
* Полный индекс сохранён для редких selectors. Он объединяет только одновременные запросы; новое обращение снова проверяет права. Детали предметов также не имеют TTL-кэша. Это осознанный обмен дополнительных чтений на актуальность прав, без заявления об ускорении picker.
* Runtime-only invalidation разрешена лишь при полном известном authoritative postimage и неизменном составе/владельце. Покупка, продажа, награда, изменение party/shop, неизвестный DTO, старый receipt и смена сессии не получают такого исключения. Поздний ответ прежнего владельца не публикуется.
* Advisory reference registry работает только внутри текущего read-only snapshot. Он ограничен 256 сущностями/8 уровнями, проверяет права на предметы, пропускает отсутствующие/неизвестные ссылки и не добавляет superset в worker catalog. Только последующий точный UUID need может взять подготовленную строку; aliases/card numbers по-прежнему разрешаются через каноничный membership query. Флаг по умолчанию выключен.
* После независимой свежей проверки полного content/rights proof конкурентные запросы могут разделить только immutable сериализацию и hash. Ключ включает caller/owner/artifact/schema/manifest/fingerprint/basic IDs/точный выбранный каталог. Worker result, RNG, персонаж и DB snapshot не разделяются. 128 pending keys, независимый fallback при заполнении, отдельная отмена waiter и удаление failed/completed flights.
* Статическая клиентская сборка переиспользует существующий чистый assemble после обычной загрузки зависимостей. Ключ содержит точный bundle и draft, различает undefined/null/non-finite числа и сессию; результат клонируется. Четыре записи и предел размера сериализации ограничивают хранение; чрезмерный/нестандартный ввод обходит кэш. Runtime, команды и разрешение прав не кэшируются. Постоянный второй slug-cache браузерного registry отключён.

Проверки: 58 frontend cases (7 файлов) и TSC; native bulk endpoint + advisory freshness/rights + immutable flights; дополнительно четыре flight cases проверяют совместное вычисление, насыщение, отмену уже ожидающего waiter, общую ошибку и свежий retry. Полная canonical equality на реальном worker: line и сохранённый через API wizard, обычный и resource-changing предметы, legacy/cold/warm/evicted/prefetch. Оба класса различны; прежние line+swordsman были двумя бойцами и не выдаются за этот новый критерий.

Wizard fixture импортирует только существующую `evidence.fields.mechanics` EFF-wizard-spellcasting из `scripts/content/data/spell-grant-abilities-20261001.json`. Source hash, projection hash и ID записаны в registry. Исторические snapshots/сертификаты не менялись, статус fixture — not_tested. Точная адресная квитанция: [JSON](PERF-01-catalog-followup.json).

Численного выигрыша нового advisory prefetch и client memo этот отчёт не заявляет. Ранее подтверждённые batch/cache показатели остаются отдельными измерениями; новые flags не включены в production автоматически.

Current-worker fixture compatibility: исторический pinnedFighter JSON сохранён неизменным. Test-only adapter добавляет 13 уже объявленных дочерних карточек двух контейнеров из checked-in public catalog. HTTP replay/rest/journey 3/3, guards closure 2/2, 11 текущих Vitest suites 85/85 PASS; ready/full trace assertions сохранены. Старые исторические readers используют прежние входные байты.
