# Подготовка инициативы на текущем коде

Три последовательные серии по 30 измерений, каждое после отдельного прогрева. Одинаковые бинарник, CJS и сборка интерфейса из **fdca59c3f2a08dd8df8f0dd6e6d1408295cf4c3d**; пакетное разрешение, mirrors и компактные квитанции включены. Это локальный Windows/native замер, не production SLA и не сравнение Linux OCI.

| Режим | Инициатива p50 / p95, мс | Бой готов p50 / p95, мс | Повторная сборка в UI |
|---|---:|---:|---:|
| baseline | 228.7 / 2327.9 | 636.4 / 2722.6 | 30 |
| options | 254.4 / 374.7 | 644.2 / 903.9 | 0 |
| options_prefetch | 276.5 / 364.2 | 385.2 / 901.3 | 0 |

Новый путь убрал 30 повторных сборок участника в браузере. p95 полного запуска 2722.6 → 903.9 мс, медиана 636.4 → 644.2 мс. Окно инициативы открывается в медиане позже: 228.7 → 254.4 мс. Это явный компромисс, а не ускорение всех показателей.

Prefetch повышает медиану подготовки options 66.7 → 114.6 мс и число SQL 15.0 → 34.0. Оставляем выключенным. В последней по времени серии полный бой быстрее; это не доказывает причинный выигрыш от prefetch.

Все 93 запуска, включая прогревы, приняли ровно одну initialize-команду, проверили её точный повтор без изменения сохранённого состояния, RNG или исходного персонажа. Ошибок страницы нет; все три стенда остановлены без ошибок. Исходники root остались неизменными. Платные запросы и изменения production отсутствуют.
