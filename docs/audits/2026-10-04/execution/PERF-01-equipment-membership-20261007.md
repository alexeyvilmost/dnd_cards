# Загрузка описаний экипировки по составу предметов

Панель экипировки формирует устойчивый отсортированный набор ID для гидратации. Перестановка тех же строк инвентаря, изменение количества или порядка слотов не создают новый display batch; добавление/удаление ID продолжает запускать обычное чтение текущего состава. Порядок отображения инвентаря и каноничные карточки/превью не изменяются. API-клиент, права, кеш, механический движок и сохранение команд не изменены.

Локально прошли 5 component tests без пропусков, scoped ESLint и полный `npm run build` с TypeScript и проверками DiceBox. Новый сценарий проверяет число вызовов настоящего адаптера компонента: после перестановки тех же двух предметов оно остаётся 1, после добавления третьего становится 2; доступные карточки остаются видимыми. Сохранены проверки занятых/пустых слотов и частичного отображения при недоступном соседе. Это доказательство сокращения повторного чтения компонента, без заявления об измеренном ускорении всего сайта.

Коммит содержит только компонент, соседний тест и этот Markdown. Он готов к отдельной интеграции после фактической выкатки A161. Разрешение облегчённого frontend-only протокола должно быть подтверждено реальным CI planning и host acceptance; один список изменённых файлов этого не доказывает. Production acceptance пока не заявляется.
