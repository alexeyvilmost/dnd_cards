## Существенные локальные остатки, которых нет среди environment gates

1. **OBS-01 step4: полный INP и React profile экипировки.** `OBS-01.md:62` и `scripts/performance/browser.mjs:116` прямо отмечают их как unmeasured. Event Timing samples не дают полный INP. Поздний React hover/selection JSDOM profile есть, но equipment click→DOM+2RAF — не component profile. Владелец OBS подтвердил отсутствие позднего полного receipt. `progress.json` помечает OBS-01 `done_local` без remaining gates, что шире фактического доказательства. Минимальное закрытие: отдельный локальный profile с настоящей агрегацией interaction latency и React profiling build для equipment/hover; либо сохранить принятый baseline как завершённый срез, а эти исходные критерии явно оставить incomplete. Docker здесь не требуется. Для step3 уже существуют **три разных** числовых наблюдения: `lock_statement_ms`, `lock_acquired_to_tx_return_ms`, `persist_sql_ms`. Они дают acquisition/удержание-до-возврата/persist proxies с RTT/scan/commit-ack погрешностью; исходный план не требовал точного PostgreSQL server time, поэтому его отсутствие не объявляется самостоятельным нарушением. Worker HTTP callback wall time/process CPU также нельзя выдавать за измеренную очередь до callback: эта граница должна остаться явной.

2. **REF-01 steps5–6: общий dispatch и roll/damage continuations ещё не вынесены.** `REF-01.md:60` это прямо признаёт. `handler.ts:5236` (`resolvePendingAttack`), `:5596` (`resolvePendingDamageReaction`), `:11828` (`executeCommand`) остаются владельцами этих больших фаз. Успех event queue не доказывает последующие извлечения. Acceptance первого среза выполнена; статус всего исходного объёма `done_local` без оговорки неточен. Минимальное закрытие: следующие отдельные cohesive transfers с до/после immutable corpus, сохраняя существующие executors; либо явный статус first-slice-complete/remaining вместо полного завершения.

3. **TEST-05 step3: exhaustive matrix ограничена `rules-core.PendingResolution`.** `pendingLifecycleCorpus.test.ts:12–15` гарантирует 15 вариантов именно этого union, 71 переход и два свежих процесса. В `SoloCombatState` есть дополнительные сериализуемые continuation: движение/reach, очереди областей и конца хода, triggered/interception, post-hit grapple, paid influence resume, death save/alert и последовательности AI. Часть уже имеет сильные JSON reload tests и S05/worker proofs; это не означает отсутствия всех проверок. Но нет общей типизированной таблицы этих полей и доказанного restart/retry для каждого; например `types.ts:403` и `:423` не входят в 15-case coverage assertion. Минимальное закрытие: составить отдельную board/worker continuation matrix, связать уже существующие доказательства, добавить только недостающие serialized worker restart/retry cases. Не переписывать текущий frozen corpus. Этот остаток локальный, не Linux/Docker blocker.

4. **TEST-03 step7 / TEST-05 step9: независимые jobs/shards не реализованы.** В `.github/workflows/ci.yml:26` один job; `run.mjs:108–160` последовательно выполняет Vitest, Go, browser и дополнительные gates. Manual запуск есть, поэтому отсутствие nightly отдельно не является нарушением альтернативы «nightly либо вручную». Целевой native бюджет уже достигнут: 4.48/18.27 минуты, и корректность это не обесценивает. Но literal step о разделении независимых jobs/shards нельзя объявлять выполненным. Минимальный путь — отдельное явно отложенное operational improvement либо изолированные shards с общим source/manifest binding; это не недоступность окружения.
