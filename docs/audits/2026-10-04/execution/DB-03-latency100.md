# DB-03: повторное измерение задержки на 100 парных примерах

**Критерий задержки не пройден. `DB_FROZEN_CATALOGS` остаётся выключенным.**
Правильность хранения и экономия места подтверждены отдельно от быстродействия.
Прежние `DB-03-storage.json` и его 30 примеров сохранены без изменений.

В спокойном согласованном окне 05.10.2026 выполнены 100 измеряемых пар OFF/ON
и пять прогревочных пар. Другие агенты приостановили Docker builds и native
наборы; команды выполнялись последовательно, порядок OFF/ON чередовался.
Один актуальный backend и один артефакт правил скопированы в обе копии БД.
Перед инициализацией подготовлены 105 настоящих забегов; обе БД восстановлены
из одного owned backup. Сверены schema fingerprint, counts и hashes полных
строк персонажей/забегов, выполнен одинаковый `ANALYZE`. Command IDs, payloads,
исходные ревизии и контент одинаковы. Игровой seed внутри каждой инициализации
остаётся настоящим независимым crypto-random: полное равенство игровых исходов
между OFF и ON **не утверждается**.

Оба варианта используют batch, preparation cache, mirrors и compact receipts;
отличается только frozen catalogs. Каждая принятая команда немедленно повторена
с тем же ID: проверены точный ответ и неизменность сохранённого состояния,
включая envelope/RNG, counts receipts/events. Перезагрузка и сохранность
исходных листов проверены для каждого боя. Итого 420 commits и 420 exact retry
requests, 210 reload checks; все три owned стенда завершены со статусом stopped.

Для init отношение p95 ON/OFF = **1,0578**; описательный 95% paired-bootstrap
интервал по 3000 выборкам — **[1,0101; 1,1407]**. Для continue: **1,0144**,
интервал **[0,9365; 1,0753]**. Это не доказательство отсутствия регрессии:
хвост initialize ухудшился, несмотря на более низкую медиану. Bootstrap
пересэмплирует согласованные индексы забегов; временную автокорреляцию и всю
неопределённость одного локального хоста он не устраняет.

Storage для всех 105 боёв: inline catalog 8 227 695 B → 210 B, одна immutable
запись 78 359 B. Сумма relation runs + catalogs: 9 936 896 → 6 889 472 B.
Это локальная физическая оценка с гранулярностью страниц, а не production размер.
SQL по init 26 → 29, по continue 14 → 17. Среднее время транзакции init
34,30 → 36,83 мс; сравнение холодных JSON полей внутри ON занимает около 1,25 мс.
Эти фазы указывают на дополнительную работу, но сами по себе не объясняют весь p95.
