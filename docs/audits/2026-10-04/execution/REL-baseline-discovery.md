# Проверка фактически выкатанной базовой версии

`scripts/release/deployed-baseline.mjs` — общий read-only discovery для `automatic-release.mjs` и повторной freshness-проверки `ci-release.mjs`. Он не публикует образы, не скачивает/исполняет артефакты и не выполняет production actions.

- Просматриваются все доступные completed workflow runs `deploy.yml` на main, включая failure. Явный completed `deploy` job со статусом skipped — noop: подтверждение выкатки от него не требуется. Отсутствующий/неоднозначный job и неизвестный исход останавливают discovery. Из остальных jobs выбирается единственный максимальный `completed_at`; его failure/cancelled/иной неуспех требует recovery. Более старая failure допустима лишь после более новой успешной выкатки.
- Для выполненного successful deploy требуется ровно один `deployed-release`, expired=false, ненулевой размер и действующий expires_at. Run ID/control SHA должны совпадать; created_at артефакта должен попадать в окно выполнения deploy job, чтобы прежняя попытка run не подменила новое подтверждение.
- Runs, latest-attempt jobs и artifacts обходятся постранично. Неполные/повторные результаты, изменение total_count или исчерпанный лимит не означают «первую выкатку»: это ошибка. Лимит100 страниц ×100 записей останавливает процесс, не выбирая устаревший fallback. Для filtered workflow runs действует более строгая граница: total_count≥1000 отвергается, поскольку GitHub ограничивает выдачу1000 результатами и полноту такой истории нельзя предполагать. Full scan необходим до выбора результата, даже если первая страница содержит success.
- Run metadata/attempt повторно читаются до и после jobs/artifact discovery. Fork, другой workflow/branch/event и неполные данные отвергаются. Token не передаётся в helper и не записывается в отчёт.
- Missing/deleted/expired подтверждение реально выполненной выкатки не разрешает переход к старому manifest. Содержимое скачанного receipt/manifest по-прежнему отдельно проверяется через `verifyBaseline`.

Локально: `deployed-baseline`, `automatic-release`, `ci-release`, `ci-policy` — **35/35 tests PASS**. Проверены101 runs,101 jobs,101 artifacts, два типа noop, отсутствующие/истёкшие receipts, недопустимые метаданные, новая попытка во время discovery, stale artifact предыдущего rerun, исчерпание100 страниц jobs с10001 total и консервативный отказ на1000/10001 workflow runs. Общий runner и внешний GitHub workflow не запускались.

Порядок создания runs не подменяет порядок выкаток. Отдельный regression воспроизводит старый manual workflow rerun, завершившийся позже нового run: выбирается его новый receipt. Ties по максимальному completed_at, неверные/незавершённые даты и изменение selected run attempt отвергаются. Одновременную выкатку после завершения discovery по-прежнему контролирует обязательный host predecessor check; GitHub history не является блокировкой production.

GitHub подтверждает, что пропущенный по условию job сообщает успешный статус, поэтому общий workflow conclusion сам по себе не доказывает выкатку: [job conditions](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-jobs-with-conditions). Pagination и latest-attempt filter соответствуют [workflow jobs API](https://docs.github.com/en/rest/actions/workflow-jobs?apiVersion=2022-11-28).
Ограничение1000 filtered results: [workflow runs API](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-workflow). Для более длинной истории требуется отдельно проверенное разбиение запросов или реестр выкаток; fallback на первую страницу запрещён.
