# DB-03: повторное чтение внутри транзакции и окончательное решение

**Latency acceptance не пройдена после исправления. `DB_FROZEN_CATALOGS=0`.
Дальнейшая настройка в этой итерации остановлена.** Экономия хранения и
сокращение числа SQL подтверждены, но не заменяют критерий задержки.

В `storage_catalog.go` добавлен небольшой scope одной транзакции: одна
сериализованная immutable запись, максимум 8 MiB, с привязкой к конкретному
transaction `*gorm.DB`; после выхода из callback данные очищаются. Чтение до
worker не переносится в транзакцию commit. Свежий `ownedRoguelikeRun` по-прежнему
проверяет владельца забега, ссылку, artifact и пустой inline slot; повторная
гидратация получает новую mutable копию и заново проверяет полный hash.
Авторитетный postimage, lock/CAS, journal и receipt порядок не изменены.

Уже существующий каталог при новом pin сначала читается и проверяется, без
лишнего `INSERT ON CONFLICT`. При отсутствии записи сохраняется прежняя
безопасная последовательность INSERT + свежий SELECT/hash, включая гонку
двух первых pins. Исторические каталоги/артефакты не переписаны; глобального
кеша или переиспользования между транзакциями нет.

Семь обязательных native PostgreSQL проверок прошли без skip в
`test_23ee5b7df661609fdb14a38c`, cleanup stopped. Новые тесты проверяют:

- Одна DB-гидратация и независимые mutable результаты; current owner/ref/artifact/
  inline и испорченный сериализованный payload отклоняются.
- Warm pin делает один SELECT, ни одного INSERT; совпавший primary key с
  повреждённым payload не принимается и не перезаписывается.
- Незакоммиченная запись и scope не переходят в другую транзакцию; rollback и
  callback exit очищают scope, autocommit не получает кеш.
- Два реальных первых pin доходят до отсутствующей строки одновременно,
  сохраняют одну проверенную запись и успешно читают её.

Независимый read-only review `tests_architecture` не нашёл остаточного блокера.
Компиляция и `git diff --check` прошли. Полные финальные suites остаются отдельной
проверкой свежего неизменного снимка.

Повторён ровно один замер: 100 пар OFF/ON и пять прогревочных пар, один current
binary/artifact, одинаковый восстановленный pre-init snapshot/command IDs/
payloads/revisions и `ANALYZE`, чередование порядка. Остальные агенты отложили
тяжёлые builds/tests. Настоящая init entropy в разных arms независима; полного
равенства разных игровых исходов не заявлено. 420 commits, 420 exact retries,
210 reload/source checks прошли, все три стенда остановлены.

Init p95 ON/OFF = **1,0624**, 95% описательный paired-bootstrap интервал
**[1,0176; 1,1062]**. Continue: **1,0504**, интервал **[0,9708; 1,2482]**.
Сравнение холодного JSON внутри ON занимает около 1,22–1,27 мс; сохранены
декодирование, копирование и hash проверки. Снижение SQL 29→27 / 17→16
подтверждено, ускорение команды не подтверждено. Две отдельные серии используют
разные новые игровые seeds/метаданные: их нельзя объявить побайтовым causal
сравнением самой правки. Финальное решение основано на отрицательном OFF/ON
результате каждого парного опыта.
