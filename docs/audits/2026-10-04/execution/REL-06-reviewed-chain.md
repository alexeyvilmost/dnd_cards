# Проверенная история двух остановленных выкаток

Добавлена явная ограниченная цепочка восстановления: исходная попытка 37273035754 остановлена во время репетиции; попытка 37287164307 отказала до capture. Для каждой сохранены точный запуск, версия, этап и hash собственного аудита. Второй документ ссылается на неизменённую первую проверенную запись. Обычный поиск успешной выкатки продолжает отказывать на неизвестной ошибке.

Сервер проверяет реальные прежние transfer-файлы и их происхождение, точную последовательность фаз, отсутствие продолжения, auth, journal, lock и временных ресурсов. Для первого отказа нужна исходная failed-репетиция с завершённой очисткой; для второго отдельно проверяется отсутствие snapshot и репетиции. Цепочка с повтором, циклом, чужим успехом, неизвестной ошибкой или иной живой операцией не принимается. Требование прав 0700 сохранено.

Локально прошли78 из 81 адресных Windows проверок; три проверки Linux-файловой системы выполнены отдельно на Linux: 16/16, без пропусков, с очисткой. Независимый review прошёл. Реальная читающая проверка GitHub подтвердила обе попытки: 45 читающих запросов, без изменений. Новые модули затем выполнили полную читающую проверку на настоящем TimeWeb: обе прежние посылки и фазы совпадают, прежний активный состав неизменен; 15 проверочных файлов и 5 каталогов удалены.

Это подготовка нового выпуска, а не успешная выкатка. Новый коммит должен пройти полный точный CI; затем нужны новая публикация, свежий capture и все обычные gates. [Машинная запись](REL-06-reviewed-chain.json).
