# Не выкатывать приложения при изменении только проверок

Скрипты testing/performance и tests/suites.json раньше попадали в неизвестные пути, поэтому выбирались все приложения. Добавлена явная категория проверки: она сохраняет обязательный extended CI. Отказ от выпуска возможен только при точном совпадении трёх образов, входов сборки с базовыми образами/аргументами, защищённой конфигурации и актуального состава входов worker. Изменённый путь в worker, новый образ, конфигурация, неизвестный runtime-путь либо отсутствие доказательства дают полный выпуск. Ветви обычного frontend-only выпуска сохранены.

78 проверок выбора, планирования, dispatch, Docker inputs и CI прошли; отдельно прошли26 проверок состояния выкатки. Интеграционный тест создаёт настоящий отдельный Git-репозиторий: diff скриптов/маршрутизации/JSON-отчёта сохраняет все три Docker fingerprint и digest; dispatch останавливается без публикации, новой копии БД и продвижения production baseline. Core вместо extended и неочищенный стенд блокируют этот путь.

Это локальная проверка. Hosted CI ещё требуется; текущая правка release-tooling сама требует полного выпуска. Фактическая выборочная выкатка фронтенда на прод всё ещё открыта. [Хеши и результаты](REL-05-verification-only-policy-20261007.json).

Дополнительно выполнен весь Node-набор release: 782 проверки прошли, ошибок нет; 10 существующих Linux-only проверок пропущены на Windows. Их обязательный hosted Linux CI остаётся отдельным требованием.
