## Границы и сохранённая диагностика

- `resolveMediaVariant` по умолчанию сохраняет originals и явно возвращает original для `purpose='print'/'export'`; его четыре unit-теста входят в полный Vitest receipt 6073/6073. Opt-in browser сборка сама по себе не проверяет отдельную сборку с выключенным flag.
- Бумажный лист действительно печатался и экспортировался. **Печать самой боевой карты не переключает CSS обратно на PNG автоматически:** текущий `TacticalBattleMap` вызывает resolver с назначением screen. Такая гарантия не заявляется. Сохранённые данные и исходные URL остаются оригинальными.
- Первый map diagnostic после зелёных 11 E2E остановился из-за ошибки тестового скрипта: original manifest row не имеет `proof.width`. Исправлено чтением PNG IHDR из сохранённого UI snapshot; приложение не менялось. Failed `media-real.json` первоначального run сохранён.
- Следующий stand `test_9595f66e17260b745ca01130` остановился на незавершённой параллельной Go-правке `CatalogSelection`; после сигнала владельца о готовности создан новый стенд. Это не browser failure.
- Все завершённые стенды остановлены. Коммит, push, TimeWeb и внешние платные API не выполнялись.

Повторяемый локальный driver: `node scripts/testing/check-media-real.mjs`; отдельные `--maps-only` и `--fixtures-only` явно обозначают неполную выборку. Текущий map driver использует принятый локальный bundle v2 и ограничивает поиск обоих естественных типов карты 16 новыми столкновениями: если оба не получены, результат failed, а не skip.
