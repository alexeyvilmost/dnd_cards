# CLEAN-02: восстановление потерянного результата без повторного удаления

Новая команда `--reconcile-character-retirement` принимает неизменный сохранённый запрос исполнения. Она читает совпадающую исходную квитанцию, восстанавливает её хеш и выполняет общую проверку результата. SQL удаления не вызывается; результат содержит пустой `applied`. При отсутствии квитанции или расхождении возвращается отказ, данные не исправляются. Исполнение и восстановление используют общий сборщик наблюдения.

Перед отправкой флага исполнитель обязан подтвердить `retirementReconciliationProtocolVersion: 1` из `--migration-info`, точные source/fingerprint и checksum302. Старый образ нельзя запускать с неизвестным флагом: такая команда могла бы перейти к обычному запуску приложения. Startup и обычный migration runner по-прежнему не удаляют старые поколения.

На отдельных owned native PostgreSQL прошли 38 проверок по8 обязательным родительским тестам, без пропусков. Проверены отсутствие квитанции, восстановление после потери ответа, поздняя играV3, оба формата хранилища команд и отказы при изменённом запросе/схеме/журнале. Все дочерние БД удалены, родительский fixture сохранён. Backend собран;41 проверка manifest/shards прошла. Первая расширенная попытка имела PASS-тесты, но завершилась exit1 из-за отказаWindows удалить временный GoTest executable; её ошибочный отчёт сохранён, отдельный повтор прошёл полностью.
