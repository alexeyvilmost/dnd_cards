# Подлинные исходные данные старых миграций

Прежний вывод об отсутствии данных перед миграцией 102 уточнён: в неизменённом защищённом снимке найдены подлинные исторические значения для миграций 102, 103 и 119. Они применяются только в изолированную тестовую БД на точных границах цепочки, после проверки происхождения, идентичности, mechanics/support и rowhash. Для миграции 122 использован точный публичный Git blob 71751d6 с проверенным hash и исходным списком классов. Сертификация не повышается, штатные guards и migrator неизменны.

Первый прогон с усиленной проверкой перед миграцией 119 выполнил неизменённые миграции до версии 123. Тогда на миграции 124 проверка состава потребовала 16 публичных сущностей и нашла 15; это исторический результат, сохранённый в первоначальной машинной записи.

Более поздняя проверка выполнила цепочку до версии 277. На миграции 278 из 1656 предусловий прошли 1045, отказали 611. Актуальная граница зафиксирована в поле `historicalFresh` [CI-13-manifest-refusal.json](CI-13-manifest-refusal.json). Полная установка остаётся незавершённой: нужны подлинные исходные данные перед миграцией 278. Импорт готовой современной схемы и успешные обновления поддерживаемых версий не доказывают выполнение этой исторической цепочки. Предусловия и статусы ручной проверки не ослабляются.

Это цепочка с явным восстановлением исторических данных, не пустая установка без каталога. Оригинальный прогон сертификации v4 не найден и не воспроизведён; отозванный сертификат не восстановлен. Успешные обновления поддерживаемых версий и CI10 учитываются отдельно. [Машинная запись](TEST-05-genuine-preimages.json).
