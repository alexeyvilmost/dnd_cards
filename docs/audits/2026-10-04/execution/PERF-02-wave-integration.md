# Повторные зависимости внутри подготовки каталога

В основной код перенесено устранение одинаковых запросов внутри одной волны подготовки. Сохраняются порядок первого появления, каноничный сборщик, ошибки неоднозначных ссылок и новые чтения в следующей волне. Общий кеш не добавлен.

На текущем коде прошли семь Go-проверок без пропусков, включая настоящий worker и группы из 1, 2 и 6 персонажей; отдельная БД и все процессы остановлены. Прошли сборки backend/worker/frontend, проверка типов фронтенда и 34 проверки выбора компонентов и происхождения исходных данных. Первая DB-only попытка сохранена как неуспешная: ей не хватало настоящего worker для обязательного сценария. Новый полный стенд выполнил и этот сценарий.

Прежние 40+40 замеров показывали для группы из 6 персонажей медиану ниже на 11,28%, p95 — на 4,64%; для одного персонажа устойчивого выигрыша не было. Это прежняя локальная серия, а не замер нового коммита или production. Сейчас на сайте включён пакетный путь, поэтому данное изменение альтернативного пути само по себе не ускоряет текущую конфигурацию.

Следом требуются точный CI и публикация полного кандидата. Источник приложения на сервере f05 отличается от служебного025: добавленная запись отказа и изменённое происхождение backend требуют полного выбора. Урезать его до frontend-only нельзя. После принятого полного baseline можно проверить подготовленное изменение только UI. Перед следующим переключением нужен свежий backup и предупреждение владельца.
