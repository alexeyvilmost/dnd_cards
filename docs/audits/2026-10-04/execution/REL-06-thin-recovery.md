# Полная проверка БД и повтор первого выпуска

Ускоренный полный обход БД интегрирован. На локально восстановленном защищённом снимке чтение всех ссылок занимает 158,7 с вместо 401,8 с; один проход истории — 43,7–44,8 с вместо 74,1–76,7 с. Результаты, количество строк, все 92 таблицы и прежний протокол хеширования совпадают. Это локальные измерения, не гарантия срока серверной репетиции.

Один постоянный курсор читает ограниченные порции внутри существующего read-only snapshot. Проверяются все JSON и объявленные текстовые ссылки, сжатые квитанции, схемы и миграции. Двенадцать независимых проходов истории сохранены. Потеря exporter, замена физической таблицы, повреждённый UTF-8, превышение лимитов и ошибки очистки блокируют принятие результата. Для чтения достаточно обычной роли SELECT.

Первая выкатка 37273035754 завершилась ошибкой до замены приложения. Повтор разрешается через отдельный явный ручной путь, связанный с проверенной записью этой конкретной попытки. Обычный поиск последней выкатки остаётся строгим. Успешная прошлая выкатка, неизвестная попытка, незавершённая операция, изменённые контейнеры, journal или lock блокируют этот путь. Сервер заново проверяет текущий main и защищённое состояние до capture и под lock перед первой записью операции.

Локальные объединённые проверки: 185 Node тестов и 18 реальных Docker проверок, без пропусков, с удалением собственных ресурсов. Отдельные исправления прошли независимый review. Старая дата backup и неуспешный статус первой репетиции сохранены. Новая попытка требует нового capture, всех обычных gates, writers OFF, точного нового коммита и полного CI.
