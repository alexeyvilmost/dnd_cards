# Публичный режим и эксплуатационные ограничения

Состояние на 2026-08-03. Сервис намеренно работает без обязательной авторизации:
анонимные запросы используют общего пользователя `public`. Это продуктовое
решение для прототипа, а не граница безопасности или изоляция данных.

Backend применяет:

- request ID и безопасные HTTP-заголовки ко всем ответам;
- лимит JSON-body 2 MiB и multipart upload 12 MiB;
- общий лимит мутаций 180 запросов в минуту на IP и endpoint;
- отдельные лимиты регистрации, входа, AI-механик, генерации и загрузки
  изображений;
- audit-log мутаций без тела запроса;
- batch журнала не более 200 событий и идемпотентность по
  `(character_id, client_event_id)`.

Лимитеры хранятся в памяти процесса. При горизонтальном масштабировании их надо
заменить общим хранилищем (например, Redis), иначе каждый инстанс будет считать
окно независимо.

`npm audit` после обновления зависимостей оставляет два high-advisory в
React Router, относящихся к RSC/server actions. Текущий frontend — клиентский
Vite SPA и эти режимы не использует; исключение контекстное и должно быть
перепроверено при появлении безопасной версии или внедрении SSR/RSC.

Удаление production-данных запрещено без отдельного подтверждения. Старые V1/V2
модели и SQL-дампы считаются кандидатами на удаление, но пока сохраняются из-за
неполной доказанности отсутствия внешних потребителей.
