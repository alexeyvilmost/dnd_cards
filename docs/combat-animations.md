# Анимации обычного 2D-боя

Анимации — отдельные метаданные представления. Они не меняют механику сущности,
стоимость, бросок, HP, сертификаты, артефакт начатого боя или сохранённую историю.

## Каталог и назначение сущностям

Единый начальный каталог — `backend/animationpresentation/catalog.json`.
Его читает Go-миграция `286_combat_animation_metadata`; этот же JSON импортирует
клиент как запасной каталог при недоступности API. Копии каталога не генерируются.
Миграция `287_combat_animation_coverage` применяет замороженную дельту второго
аудита. Новые назначения добавляются только присутствующим сущностям и не
заменяют выбор администратора. Прежние seed-профили обновляются только при
точном совпадении JSON с предыдущим значением; удалённые назначения первого
каталога не восстанавливаются.
Миграция `288_force_animation_palette` переводит 18 исходных профилей чистой
силы в красную палитру (`#ef4444`, светлый акцент `#fecaca`), включая лучи,
снаряды, всплески и магические круги. Она также сохраняет ручные изменения
профилей. Правило `defaults.damagePalette.force` позволяет обычному оружейному
удару сохранить форму при замене его урона на чистую силу и получить ту же
красную палитру.
Миграция `290_critical_weapon_animations` добавляет отдельные варианты
критического оружейного попадания. Она только вставляет отсутствующие профили:
обычные профили, ручные настройки и привязки сущностей не меняются.
Миграция `292_critical_spell_animations` добавляет критические варианты лучей
и магических снарядов, включая ледяной кинжал. Магический вариант помечен
`criticalEffect: "magic"`; он сохраняет исходный мотив и цвет, в том числе
красный цвет чистой силы. Это не добавляет заклинанию право на критический
урон: вариант выбирается только по подтверждённому исходу атаки.

Миграция создаёт две отдельные таблицы:

- `animation_profiles`: устойчивый ключ и JSON-описание профиля.
- `entity_animation_bindings`: тип и устойчивый ID сущности → ключ профиля.

Профиль содержит `primitive`, `palette.primary/secondary`,
`motion.durationMs/scale`, `casterCircle` и необязательный `motif`.
Для метательного оружия `weaponShape` выбирает форму снаряда (`blade`, `axe`,
`hammer`, `spear`, `stone`). Это оформление, оно не задаёт дальность или урон.
`defaults.criticalProfile` связывает обычный профиль с критическим. Вариант
содержит `strikeStyle: "critical"`, `baseProfileKey` и собственную длительность,
масштаб и доли фаз `motion.launchRatio/contactRatio`. Эти фазы общие для
рисования, контакта с целью и звука; `baseProfileKey` сохраняет возможность
наследовать звуковое оформление исходного профиля. Подтверждённый исход выбирает
вариант через данные, без распознавания названия способности.
Одна сущность может использовать тот же профиль, что и другая. Примитив задаёт
способ отрисовки (например, укус, снаряд, луч, рука, плети или скрытие), мотив —
характер магии (огонь, холод, яд, излучение и другие).

`GET /api/animations` требует входа и возвращает профили, назначения и общие
fallback-правила. `PUT /api/animations/entities/:type/:id` доступен администратору
контента и принимает `{ "profile_key": "spell.fire-bolt" }`. Пустой ключ удаляет
назначение. Запись проверяет существование незакрытой сущности и профиля, затем
сохраняет назначение транзакционно. Разрешены типы `spell`, `action`, `card`,
`effect`; привязки текущего каталога используются для действий и заклинаний.
Оформление меняется без редактирования JSON механики.

`useAnimationCatalog` загружает серверные настройки с общим кешем запроса.
Событие окна `animation-catalog-changed` обновляет каталог. Серверный список
назначений заменяет запасной, поэтому удалённое администратором назначение
не появляется повторно из локального seed. Ошибка загрузки не мешает бою.

`resolveCombatAnimation` ищет назначение по каноническому `spell.entityId`, ID
действия и `sourceEntityIds`. Привязки имеют приоритет. Если у самого действия
нет назначения, учитывается назначение сущности-источника: это
покрывает последующие действия, предоставленные заклинанием, эффектом или предметом.
Для остальных сущностей используются общие данные: `activation.counts_as`, тип урона, школа
заклинания, подтверждённый тип события и визуальный тип оружейной атаки.
Для заклинаний event-fallback берётся из отдельного `defaults.spellEvent`:
лечение, временные HP и другие spell-события сохраняют магический круг.
Остальные заклинания используют тип урона/школу до общих профилей событий действий.
Распознавания по названию, описанию или веток с конкретными UUID в runtime нет.

## Оружие и сохранённый контекст атаки

Каноническая запись атаки может иметь системный ID (`core.attack.weapon`),
отличающийся от ID кнопки в каталоге. `combatAnimationAction` разрешает её по
`sourceEntityIds` и сохранённому `declaredActionId`, а при необходимости использует
существующие канонические определения системных атак. Для старого текста без
структурированного происхождения остаётся прежний адаптер журнала.

`combatAttackPresentation` использует общий `bindEquippedWeaponActionContext`,
`weaponAttackKind`, `weaponContext` и `parseWeaponProfile`. Он учитывает основную
и вторую руку, выбранную дальнобойную атаку и сохранённый `facts.weaponCardId`
либо источник `card:<id>`. Естественная атака со своим уроном не заимствует
оружие из рук; её явное назначение сохраняется у производной провоцированной
атаки. Это исправляет случай, когда огненный укус гончей ошибочно становился
ударом молота, а системная атака мечом теряла ссылку на экипированный меч.

Новые записи сохраняют `attackPresentation` при выполнении: визуальный тип,
тип урона, ID и каноничный тип оружия, его свойства и исходный тип урона.
Продолжение после реакции наследует этот снимок. Смена или удаление оружия,
а также перезагрузка, не меняют уже сохранённое оформление атаки.
Структурированные факты `ActionDeclared` теперь сохраняются в проекции журнала.
Предыдущие записи не дополняются задним числом.

Для обычных дальнобойных атак общие таблицы `defaults.rangedWeapon`,
`defaults.rangedDamage` и `defaults.weaponProperty` выбирают пистолет/мушкет,
метательное оружие, камень или стрелу по каноничным данным предмета.
Форма рубящего/колющего удара берётся из физического профиля оружия, даже если
магическое свойство заменило нанесённый урон на другой тип. Палитра применяется
отдельно через `combatDamagePalette` и `defaults.damagePalette`: чистая сила
остаётся красной и у оружейного удара. Если окончательный тип урона появился
только в подтверждённом событии урона, палитра обновляется у того же действия,
без замены его примитива и повторного броска.

## Области на поле

`CombatBeat.area` передаёт рендереру снимок геометрии, позиции источника,
начала области, выбранной точки направления/центра и затронутых клеток.
Он создаётся для новой принятой декларации общими `tacticalAreaGeometry`,
`areaEffectOrigin` и `areaPositionsForAction`, которыми пользуется выбор целей.
Рендерер не задаёт дальность, размер или цели по имени заклинания/дыхания.
Координаты обозначают клетки, размеры задаются в футах; список клеток сохраняет
результат отсечения стенами. Конус/линия начинаются у источника, сфера/куб —
в принятой точке, эманация привязана к источнику согласно данным механики.

Продолжения спасбросков получают область исходной декларации. Вся область
анимируется один раз, последующие получатели сохраняют собственные броски,
урон и подписи через `suppressAnimation`. Объединение строк спасбросков не
повторяет сотворение; отдельные перемещение и смерть не наследуют область
и не подавляются этим правилом. Дыхание использует профиль без магического
круга, заклинание — с кругом.

Старые закреплённые боевые артефакты могут создавать записи с принятой
`targetPosition`, но без нового снимка области. Для них существует только
проекция чтения: та же каноническая геометрия и сохранённые точки перемещений
восстанавливают положение источника, когда история это позволяет. Если точек
нет, используется текущая позиция для немедленного визуального отклика.
Это приближение для давней истории; точное прошлое положение без сохранённых
координат восстановить нельзя. Проекция не перезаписывает журнал, артефакт,
список целей или результат действия.

линейные профили также доступны, но не меняют геометрию этих действий.

Проверены 24 библиотечных монстра и все их 40 различных действий. Три личных
QA-манекена из локальной БД не вошли в библиотечный seed. Привязки различают
укус гончей с огнём, ядовитый и обычный укус, кулачный удар, захват, рубящий и

новых существ; у текущих монстров таких атак нет, поэтому им не выдумываются
несуществующие действия.

Всего в текущем каталоге: 194 профиля, 240 исходных назначений. Из них 16 —
отдельные критические варианты рубящего, колющего и дробящего удара, стрелы,
метательного оружия и огнестрельного выстрела. Они включают отравленную стрелу,
«Меткий удар» и четыре оружейные кары, сохраняя палитру, форму оружия и круг.

накопление энергии, быстрый выброс и отдельный магический контакт. Области,
укусы и спасброски не получают оружейный критический удар.
Миграция записывает только
назначения сущностей, присутствующих в установленной библиотеке. Список
`cantripCoverage` содержит устойчивые ID и человекочитаемые подписи для аудита;
`levelOneCoverage`, `monsterCoverage` и `breathCoverage` документируют второй
аудит. Эти списки не участвуют в runtime-выборе анимации.

Источники локального аудита: `outputs/combat-animation-286/catalog.json`
(read-only экспорт локальной БД) и
`outputs/catalog-completion-20260929/spells.json` (уже имеющийся снимок).
Оба файла — локальные проверочные материалы и не нужны при сборке или запуске.
Второй read-only экспорт: `outputs/combat-animation-v2/{monsters,actions,spells,level1spells}.json`.

## Срок действия и подтверждение

Круг сотворения масштабируется по сохранённому уровню применения заклинания.
Длительные круги строятся `resolveActiveSpellCircles` из действующего состояния:
активных эффектов с доказуемым `spellOriginId`/`magicOrigin`/контекстом применения,
концентрации, областей, магических объектов, присоединённого света/магических
меток и существ, принадлежащих призыву. Круг расположен у сохранённого источника
заклинания. Несколько получателей одного заклинания не дублируют круг.

Сохранённый `castLevel` приоритетнее базового уровня, если он присутствует у
эффекта; для старых объектов/областей без сохранённого повышения доступен только
базовый уровень. Отсутствующая provenance не восстанавливается по названию.
Истечение/снятие убирает круг вместе с авторитетным состоянием. Перезагрузка
восстанавливает действующие круги, но не воспроизводит историю ударов.

Очередь анимаций получает подтверждённые записи. Предварительный бросок перед
влиянием не даёт анимации попадания/промаха или окончательных последствий.
`prefers-reduced-motion` сохраняет читаемое оформление без движения.

источника на общих примитивах, замену/удаление серверных назначений без изменения
механики, покрытие заговоров и укусов, fallback и сроки жизни кругов, сохранённое
повышение уровня, перезагрузку, независимые источники и магические вложения

`animationCommit.test.ts` проверяет настоящий локальный путь команд для разных

источника, спасброски нескольких целей дают одну область, перезагрузка и чтение

основную/вторую руку, системное происхождение атаки, естественные атаки,

## Локальный запуск этой итерации

Интерфейс работает на `http://localhost:3002`, API — на `127.0.0.1:8082`,
worker — на `127.0.0.1:8092`. Для анимаций создана отдельная локальная копия
БД `combat_animation_286_20260929`; исходная рабочая БД сохранена. Резервная
копия находится в `outputs/combat-animation-286/`, новые проверочные материалы —
в `outputs/combat-animation-v2/`. Порты 3001/8090 заняты другим локальным
checkout; его процессы сохранены.

Обычный запуск миграций на копии выявил несовпадение preimage у ранее
существовавшей миграции `278_catalog_mechanics_audit`. Для изолированной
проверки анимаций `scripts/build-combat-animations-local.ps1` собирает локальный
Go overlay, который допускает только названную loopback-БД и исполняет только
миграции анимаций 286–288, 290 и 292. Остальные отсутствующие миграции явно остаются pending;
их успешное применение не имитируется. Production-путь миграций не изменён.
Этот локальный запуск не является подтверждением готовности production-релиза.

`scripts/start-combat-animations-local.ps1 -Service api` запускает этот API,
`-Service worker` — локальный worker с сохранением каталога старых артефактов,
`-Service frontend` — Vite с прокси на этот API. Порты можно задать параметрами
`-ApiPort`, `-WorkerPort`, `-FrontendPort`.
Секреты читаются из существующего локального environment-файла.

`scripts/roguelike/combat-animations-local.mjs` проверяет все 149 профилей,
совпадение центров эффектов и токенов, уровни кругов, промах, ожидание реакции,
уменьшенное движение и мобильный экран. `combat-animations-live-local.mjs`
проверяет авторизацию API и обычную команду рывка в новом QA-бою на копии БД,
повтор команды и перезагрузку настоящей страницы боя. Новый
`combat-animations-v2-local.mjs` читает локальный снимок без API-запросов,
проверяет сохранённые атаки, фазы двух лучей и шесть геометрий областей.
Подробные результаты этой итерации — в `docs/combat-animations-v2-local-20260929.md`.
