# Контракт data-driven механик

Зафиксирован по требованиям владельца проекта, 15.09.2026. Это действующий контракт, а не утверждение, что весь исторический движок уже ему соответствует.

## Фазы разрешения

| Конвейер | Порядок |
| --- | --- |
| Атака | до броска → кости/модификаторы → влияние после броска, до исхода → исход → попадание/промах |
| Урон | до броска → кости/модификаторы → влияние после броска → до нанесения/получения → сопротивления, уязвимости, иммунитет → применение → после нанесения/получения |
| Эффект | конвейер спасброска при необходимости → до наложения/получения → применение → после наложения/получения |
| Спасбросок | до броска → кости/модификаторы → влияние после броска → исход → успех/провал |
| Проверка | до броска → кости/модификаторы → влияние до исхода → исход → успех/провал |

Предикаты на выпавшие грани проверяются в фазе после соответствующего броска. Начало/конец хода, шаг перемещения, расход ресурсов, короткий/долгий отдых — самостоятельные события. Исследование и лист используют те же операции, а не отдельные реализации правил.

## Граница данных и кода

Теги библиотеки хранятся в общем справочнике `entity_tag_definitions` и назначениях `entity_tag_assignments`. Связь магазина с тегом задаётся ID в `roguelike_shop_settings`, а не проверкой его названия. Теги не смешиваются с внутренними runtime-тегами эффектов и объектов. Поле `legacy_tags` и его старое wire-имя `tags` сохраняются только как неизменяемые снимки для проверки ранее выданных сертификатов; записывать в них новые метки нельзя. Метаданные редактируются отдельным авторизованным API и не переписывают боевую историю.

Представление сущности также является контрактом: использовать каноничный компонент её типа, его превью и настройку иконка/строка. Контекст выбора добавляет выделение, доступность и подтверждение, но не заменяет действие или заклинание произвольной кнопкой с названием. Это обязательно для влияния на броски и подготовки заклинаний при отдыхе.

В коде допустимы `reroll_kept_d20`, удаление состояния, проверка цены, доля скорости, проверка диапазона граней. Имя способности, источник, иконка, цена, подходящие броски/фазы и порог кости принадлежат данным. Неизвестную операцию нельзя считать исполненной.

UI получает доступные действия, показывает стандартную карточку и посылает идентификатор выбранного действия. Авторитетная сторона заново собирает предложения и проверяет стоимость. Предпросмотр исхода не изменяет HP, инвентарь или ресурсы. Окончательный исход публикуется после решения.

## Проверка изменений

- Вторая сущность на том же примитиве работает без новой кнопки: иной ресурс, порог к20, название и превью.
- Нет подходящих граней/фазы/ресурса — действие не предлагается; подделанный выбор отклоняется.
- Сохранение и продолжение не дают повторного расхода. При отказе сохраняется первоначальная кость.
- Действие состояния исчезает вместе с источником; стоимость рассчитывается от актуальной скорости, не остатка движения.
- КД в деталях — снимок вычисления, а не догадка по экипировке после хода.

## Аудит

Обнаружены отдельные ветки вдохновения в листах, боевом продолжении и UI, отдельная кнопка вставания, неодинаковые подписи КД. Также существуют специализированные адаптеры реакций, освобождения из захвата и управления длительными заклинаниями. Их перенос требует отдельных тестов продолжений; переименование ветки само по себе не считается устранением нарушения. Исторический обзор `engine-architecture-review-2026-07-07.md` описывает состояние на июль и не заменяет проверку текущего кода.

### Реализовано в этой локальной итерации

- `engine/rollInfluence.ts`: сбор действий из деклараций системных правил, пассивов и активных эффектов; фильтры типа броска и грани; общая оплата через `cost.ts`. Первая системная декларация — JSON вдохновения, не ветка в UI/исполнителе. Тестовое кольцо с иным ресурсом и порогом демонстрирует расширение данными.
- Сериализуемое решение `roll_influence`, выбор по идентификатору действия, перепроверка предложения, сохранение исходных случайных значений и отложенное применение результата. Листы используют тот же сборщик/оплату/операцию переброса.
- `engine/conditionActions.ts`: действия предоставляются состояниями. Старое декларативное `movement_options` преобразуется в выдачу действия; новые состояния могут объявлять `world_facts.granted_actions` напрямую. «Встать» — JSON-декларация, цена — доля актуальной скорости; оплата через общий cost-пайплайн, удаление состояния через общий исполнитель. Старый `stand` оставлен только как совместимый вход для архивных команд/AI.
- Общее отображение `SheetActionLine`/`ActionPreview`/`SpellPreview`, настройки каждого типа; подготовка после долгого отдыха сохраняет ID и предвыбор. Исправлен также общий выбор предметов и действий. Межперсонажные к20-реакции используют то же отображение действий.
- Раскрываемый расчёт атаки/КД и снимок `ValueBreakdown` цели. Подписи КД унифицированы; исторические описания локализуются при отображении, без изменения подписанного контента и журналов.

### Важные границы

Текущий примитив ручного влияния — один переброс используемой к20. Это не универсальное исполнение всех возможных вмешательств в урон, массовые броски и многократные цепочки реакций. Конвейер доработан на существующей модели сохранённого продолжения первого к20, а не заменён целиком новой шиной событий. Специализированные UI освобождения из захвата, Перехвата, обмена инициативой и управления длительными заклинаниями остаются предметом следующего архитектурного прохода. Полный аудит всех исторических механик не объявляется закрытым.

Существующие бои остаются привязаны к своим артефактам. Для их UI есть read-only адаптер прежнего сохранённого решения; новый протокол действий состояния обозначается capability-маркером. Нельзя переписать artifact hash у начатого боя ради включения нового поведения.

### Воспроизводимая проверка

- Пассивные переключатели отображаются единообразно через `SheetPassiveToggle`: круглая 48px разновидность `SheetActionLine`, стандартный `EffectPreview`, `aria-pressed`, две противоположные орбитальные искры только у включённых. При `prefers-reduced-motion` искры неподвижны. Это явно запрошенный вид управляющих пассивов; обычные действия и заклинания сохраняют настройку иконка/строка. Изображения наследуются по parent action ID, описания и отдельные значки политик/искусности задаются JSON-метаданными, без изменения игровых правил.
- `scripts/roguelike/passive-icons-local.mjs`: read-only проверка полного боевого UI на изолированном снимке QA-забега; четыре иконки одинакового размера, реальные картинки родителей, подробные каноничные превью, включение/выключение, вращение, reduced motion и 390px. Для изображений родителей браузеру нужен доступ к публичному хранилищу сайта.

- `engine/data/decisionPolicies.json` задаёт текст, область, предикат, селектор механик и начальное значение переключателей. `decision_policies` в механике может явно подключить зарегистрированную политику; для существующих AC-защит есть селектор по эффектам, без имён/UUID. Реакционные предпочтения раздельны для каждого action ID, сохраняются в настройках пассивов браузера. Оба новых фильтра по умолчанию выключены.
- Политика `attack_not_successful` пропускает предложение только при сохранённом исходе hit/crit против КД. Спасброски, проверки и натуральная 1 с большой суммой остаются доступными. Клиент отправляет обычный отказ от вмешательства; авторитетный worker продолжает сохранённый бросок, не списывая вдохновение.
- `changes_attack_outcome` использует read-only `previewAttackDefense`: та же подготовка источника заклинания, исполнитель и проекция КД, что при настоящей реакции. Превью изолировано от состояния, случайные/неподдержанные расчёты остаются неизвестными и не скрывают выбор. Это фильтр текущего попадания, не оценка полезности защиты до следующего хода. Другие триггеры (включая «Волшебную стрелу») не отбрасываются по сравнению КД.
- Held→committed обновляет один экземпляр диалога до отрисовки кадра. Сохраняется 3D-кость; новый урон анимируется отдельно. Формула и детализация общие для атаки и защитной реакции. Существующим боям не меняется артефакт.
- Редактируемое оформление переключателей хранится отдельно в `passive_presentations`: ключ связывает представление с политикой/выбором, но изменение имени, текста или картинки не меняет предикат, стоимость, значение настройки и исполнение. UI использует каноничный компонент и серверный каталог; конструктор не принимает исполняемый JSON.
- Геометрия крупных существ принадлежит версии тактических правил: новые встречи с `tacticalFootprints: "sized"` учитывают полную занимаемую область во всех пространственных проекциях. Отсутствие маркера сохраняет прежнюю клеточную геометрию архивного исполнителя. Нельзя молча увеличивать старые токены только в UI, оставляя иной расчёт у worker.
- `scripts/roguelike/decision-policies-local.mjs` после создания свежего QA-аккаунта: реальная команда отказа worker, неизменность DOM окна/кости и ресурса; затем изолированные снимки с перехватом всех команд для проверки автоотказа, реального каталога Щита, переключателей, перезагрузки и 390px. Синтетические броски не сохраняются в БД.

- TypeScript: `tsc -b`; адресные engine/solo-combat/диалоговые тесты.
- `scripts/roguelike/templates-local-acceptance.mjs`, затем `polish-local-acceptance.mjs`: новый QA-бой, сохранение/перезагрузка решения, один расход вдохновения и стрелы.
- `scripts/roguelike/entity-presentation-local.mjs`: реальная локальная библиотека, сборщик подготовки и ChoiceDialog, оба режима, стандартное превью, выбор/подтверждение, 390px. Это браузерная интеграция диалога, без изменения боевого персонажа и без фиктивного отдыха чужого листа.
- Переключаемые пассивы листа и хотбара используют один сборщик представлений канонического актёра и один реактивный набор предпочтений браузера. Дополнительные кости принадлежат `RollLog`, а не названию эффекта: общий трей отображает размер, источник, знак и сохранённое значение. UI не бросает заново дополнительную кость ради анимации и не выделяет отбрасываемую к20 до остановки обеих костей.
- Общий боевой каталог не хранит под одним ID персональный кубик/характеристику одного участника. Превью может показывать привязанный профиль, но каноническое действие сохраняет исходную декларацию; исполнитель привязывает её к действующему персонажу и текущему снаряжению. Проверять смешанную группу и две разные декларации профиля. Геометрия процедурной карты вместе с зерном и версией сохраняется в бою; перезагрузка не генерирует новую расстановку, а встроенные в фон объекты не перемещаются генератором.
- Нативные hover-подсказки через HTML `title` не используются: пояснения принадлежат существующим превью или явному тексту интерфейса. Иконки сохраняют доступные названия, дополнительная информация — ARIA-описания. `nativeTooltipPolicy.test.ts` отличает атрибуты DOM от видимых заголовков пользовательских компонентов и защищает приложение от повторного появления системных подсказок.
