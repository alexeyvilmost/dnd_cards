# Диагностика генерации изображений

Актуально на 2026-10-08. Принят выпуск `24866cda598536247ce99bbf389e84abf24c7bbb`; он сохраняет проверенный backend от `78cdd7d2`. Приватный gateway работает, writer заданий включён. Владелец подтвердил генерацию в приложении; платный локальный тест пропущен по его указанию. [Итоговая проверка выпуска и ограничения](audits/2026-10-04/execution/FINAL-original29-20261008.md).

Сохранённая исходная диагностика: генерация использует Images API и модель `gpt-image-1`. Прямой читающий запрос с TimeWeb подтвердил 403 `unsupported_country_region_territory`; [исходная диагностика](audits/2026-10-04/execution/AI-03-provider-diagnostic.json). Через постоянный приватный Sota CONNECT gateway тот же ключ успешно выполнил **один Images POST**: PNG 1024×1024, качество low, 1326241 байт, HTTP 200, около 11 секунд, без повторов. [Результат реальной генерации](audits/2026-10-04/execution/AI-03-sota-image-probe.json). TLS проверен; ключи, профиль VPN и изображение не включены в публичные отчёты. Сетевой путь и ответ провайдера подтверждены этой исторической проверкой. Она не заменяет проверку прав аккаунта или каждого будущего запроса.

## Договор об ошибках

Ответ сохраняет человекочитаемое поле `error` и добавляет `code`, `source`, `outcome`, `request_id`. Если upstream вернул ответ, доступны `provider_status`, безопасные `provider_code/type`, `provider_request_id` и категория content type. Произвольное тело/сообщение upstream, prompt, API key и base64 не включаются в диагностику.

| code | Значение | Проверка |
|---|---|---|
| content_admin_required | Приложение не разрешило операцию | Права администратора контента; OpenAI ещё не вызывался |
| image_provider_not_configured | Нет настроенного клиента | Наличие конфигурации без вывода ключа |
| image_region_unavailable | Upstream указал unsupported_country_region_territory | Поддерживаемое размещение и допустимость доступа аккаунта/пользователей |
| image_provider_permission | Upstream сообщил о правах/проверке организации | Проект ключа и доступ к конкретной модели |
| image_provider_forbidden | Неуточнённый upstream 403, в том числе HTML от edge | Content type, request ID, сеть; не считать доказанным региональным отказом |
| image_provider_authentication | Upstream 401 | Проект и ключ; не разлогинивать пользователя сайта |
| image_provider_limit | Upstream 429 | Код лимита/бюджета, настройки аккаунта |
| image_timeout / image_network_error | Нет достоверного ответа | Возможен уже выполненный платный запрос |

Upstream 401/403 не возвращаются как локальные 401/403: ответ приложения имеет 502 (либо 503 для лимита). Это предотвращает ложный выход пользователя из аккаунта. Локальный content admin запрет остаётся 403. При context deadline ответ 504; отмена клиентом — 499.

`outcome=not_started` означает, что провайдер не вызывался. `rejected` — получен 4xx-отказ. `unknown` — нельзя установить, была ли выполнена генерация. Автоматического повтора платного POST по timeout/reset/EOF нет. Новый запрос пользователя остаётся отдельной платной операцией; для фонового режима повтор использует сохранённый ID задания (описан ниже).

## Процедура проверки

1. Найти номер запроса в интерфейсе/ответе и ту же запись backend. Проверить source и provider_status. Не копировать полный заголовок Authorization, prompt или тело изображения в отчёт.
2. Проверить, есть ли реальные настройки `OPENAI_API_KEY`, `OPENAI_BASE_URL`, `OPENAI_CONNECT_PROXY_URL` именно у контейнера. В отчёте записать только факт настройки и схему маршрута. Не выводить полный URL с userinfo или query: они могут содержать секреты.
3. Для отдельно разрешённой диагностики production проверить DNS/TLS/egress из того же network namespace. Не менять глобальный маршрут хоста и не отключать TLS. Не передавать ключ случайному relay.
4. Проверить правильный проект/организацию и доступ к `gpt-image-1`. Успешный GET моделей не доказывает доступ к Images API. Пробную платную генерацию выполнять только в согласованном бюджете.
5. Региональный отказ решается поддерживаемым сценарием размещения и доступа либо доступным провайдером. VPN server на исходной машине не меняет её egress; иностранный адрес сам по себе не доказывает допустимость использования.
6. При сетевой проблеме выбирать client-only proxy либо изолированный сервис генерации. Клиент OpenAI не наследует глобальные proxy/NO_PROXY; отдельно тестировать worker/DB/storage, потерю egress и возврат конфигурации на локальном стенде до изменения TimeWeb.

Причина production 403 установлена читающим запросом: региональный отказ. Автоматические tests используют собственные серверы и не обращаются к OpenAI; отдельные эксплуатационные проверки с Sota описаны ниже.

## Фоновые задания

Миграция 300 добавляет `image_jobs`. Новая запись включается только `IMAGE_JOBS_ENABLED=1`; исходное значение — выключено. Все три вида генерации используют общий сервис. Клиент сначала проверяет `/api/images/jobs/capabilities` и для фонового режима отправляет запрос в один из job-only маршрутов `/api/images/jobs/generate`, `/generate-standalone`, `/generate-card` с `Idempotency-Key`. Ответ 202 содержит `job`; клиент читает `/api/images/jobs/:id`, история — `/api/images/jobs?page=1`. Успешный результат содержит прежние поля, поэтому редакторы сущностей продолжают получать каноничную ссылку изображения. Новый ID при выключенном writer получает 503 `image_jobs_disabled`, без синхронной генерации. Сохранённый ID обходится без capability negotiation и отправляется только в job-only маршрут; старый backend не может молча превратить такой повтор в платную синхронную попытку.

Клиент сохраняет UUID запроса под SHA-256 от аккаунта, маршрута и параметров. Prompt, ключ API и токен в этой записи не хранятся. Если браузер не может сохранить UUID, платный запрос не начинается. Потерянный ответ, закрытие окна, перезагрузка или повтор формы сохраняют этот UUID. История доступна в студии изображений; страницы содержат до 20 заданий только владельца, доступны переходы между страницами и повторное чтение после ошибки сети. Закрытие окна отменяет ожидание, но уже принятое задание продолжает выполняться.

В совместимом синхронном режиме перед запросом также сохраняется локальная квитанция. Неопределённый результат блокирует повтор того же содержимого, в том числе после включения фонового режима. Активную попытку подтвердить как новую нельзя; после перезагрузки пользователь видит неизвестный исход и отдельное предупреждение о возможной повторной оплате. Подтверждение только снимает локальную блокировку, само не вызывает API генерации. Эта локальная защита не обещает серверную идемпотентность старого синхронного API или защиту от одновременно начатых разных запросов в нескольких вкладках.

Admission, лимиты и claim используют PostgreSQL transaction/advisory lock. Перед исполнением заново проверяются администраторские права и наличие сущности. Ссылка сущности и успех задания фиксируются одной транзакцией. Running lease — пять минут; просроченная попытка становится `unknown` и никогда автоматически не отправляется провайдеру повторно. История сохраняет её неопределённость. В интерфейсе отдельное действие разрешает новой форме получить новый UUID; это действие само не запускает генерацию. Даже при выключении writer повтор уже существующего UUID остаётся чтением прежнего задания.

Настройки: `IMAGE_JOBS_MAX_DAILY_ATTEMPTS=20` (общий скользящий период 24 часа), `IMAGE_JOBS_MAX_PENDING_PER_USER=3`, `IMAGE_JOBS_MAX_CONCURRENCY=1`. Это ограничение числа принятых заданий, а не денежная квота. Дополнительно задаётся бюджет проекта у провайдера. Автоматического повторения paid POST нет. Заявление «exactly once у внешнего провайдера» не делается: при обрыве сети его результат может быть неизвестен.

Prompt необходим исполнителю и хранится в приватной таблице. SQL-логирование admission/result отключено; в общих логах только безопасные коды/ID. Удаление старых job receipts не включено: без отдельной retention-политики повтор старого UUID обязан оставаться безопасным. Резервная копия всей БД включает задания.

## Изолированный выход к OpenAI

`OPENAI_CONNECT_PROXY_URL` применяется только к HTTP-клиенту OpenAI. Допустим HTTP или HTTPS CONNECT proxy; адрес назначения обязательно HTTPS. Исходный TLS-сертификат провайдера проверяется обычным способом. Ошибка настройки останавливает запрос без direct fallback; URL с паролем не включается в сообщения. `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` больше не определяют маршрут этого клиента. При переходе со старой конфигурации перенести только проверенный адрес в новую переменную.

Схема: backend → приватный CONNECT gateway → Sota Finland → Images API. Gateway требует отдельный пароль и разрешает только `api.openai.com:443`. После временной проверки на TimeWeb запущен постоянный сервис из `infra/compose.image-egress.yml`, с автоматическим запуском после перезапуска сервера. Он работает непривилегированным пользователем с read-only filesystem, снятыми capabilities и ограничениями памяти/CPU, без опубликованных портов, TUN, NET_ADMIN и изменений default route. [Повторный запрос через постоянный gateway](audits/2026-10-04/execution/AI-03-sota-permanent-provider-probe.json) получил 200. Временные контейнеры удалены. Текущий backend подключён к постоянному gateway через приватную настройку `OPENAI_CONNECT_PROXY_URL`; её значение не выводится в отчёты.

Факт доступного IP не отменяет требований OpenAI к поддерживаемым странам и допустимости доступа: [официальные условия доступности](https://help.openai.com/en/articles/9131992-chatgpt-and-api-services-in-unsupported-countries-and-territories), [список поддерживаемых стран API](https://help.openai.com/en/articles/5347006-openai-api-supported-countries-and-territories). Сначала классифицировать фактический 403; при запрете по аккаунту/региону выбирать поддерживаемое размещение и допустимый сценарий либо другого провайдера.

Локальные проверки используют собственные TLS-origin/CONNECT servers. Подтверждены отказ для недоверенного сертификата, отсутствие Authorization провайдера в CONNECT-заголовках, невозможность NO_PROXY обойти выбранный gateway, отказ для неправильного URL и сохранение TLS verification. Полный локальный сценарий проверил реальную игру и загрузку в storage во время отказа CONNECT, затем восстановление: [AI-03-egress-isolation.json](audits/2026-10-04/execution/AI-03-egress-isolation.json). Откат: выключить writer (history/readers оставить), вернуть прежнюю корректную настройку выхода; не удалять `image_jobs`.

## Эксплуатация Sota

Подготовка профиля выполняется локально: `node scripts/image-egress/prepare-sota.mjs .env outputs/operations/sota-private/device-id outputs/operations/sota-private-NEW`. Каталог результата должен быть новым; файл ID устройства сохраняется между обновлениями, `SOTA_ID` остаётся локальным. На сервер передаётся только ограниченная конфигурация, а не мастер-ключ подписки. `sota-config.mjs` отбрасывает TUN, DNS и правила маршрутизации поставщика, проверяет TLS и создаёт отдельный пароль CONNECT. API Sota может измениться: перед обновлением сверять адрес с официальным Linux-клиентом, не отправлять ключ неизвестному зеркалу.

Использован `sing-box 1.13.8` из [официального Linux-пакета Sota](https://storage.sota.ac/api/v1/public/storage/sotavpn-latest-x64.deb): SHA-256 пакета `f19b65085a422fee12c4c29f64115238cc42b39dd16ef22ef533088354152093`, бинарника `83b7846dc85ffb1f64c1d14f63eba2fcf3d3b19ed4049c2fcd291ed6c29b5cc2`. Плавающее имя скачивания не служит идентичностью: проверять конкретные байты. GUI и системный daemon Sota не устанавливались.

Для постоянного Compose задать приватные пути `SOTA_BINARY_FILE` и `SOTA_GATEWAY_FILE`; gateway-конфигурация читается только root и UID/GID 65534 (0640), бинарник — 0755. Профиль и пароль никогда не помещаются в Git, отчёт или аргументы команд. В приватном backend environment задать `OPENAI_CONNECT_PROXY_URL` с именем `image-egress:18080` и сгенерированными учётными данными. Запуск gateway не меняет окружение уже работающего backend. Смена профиля: проверить новую конфигурацию и путь локально, сохранить прежнюю защищённую конфигурацию для отката, заменить файл и перезапустить только gateway. Не добавлять прямой fallback при обрыве VPN.
