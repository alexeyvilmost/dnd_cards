## Проверки

HTTP-интеграция и миграционные тесты на отдельном PostgreSQL покрывают извлечение,
уровни, псевдонимы и их неоднозначность, все типы каталога, частичные черновики,
обновление/очистку/удаление, откат транзакции, повторный расчёт, фильтрацию до
пагинации, авторизацию, приватность и сохранность исторической сериализации.

Живой API проверен по 11 сценариям. Пять браузерных сценариев проверяют фильтры
эффектов, показ уровня источника, перезагрузку, конструктор класса и экран 390px.
Нет ошибок JavaScript или горизонтального переполнения. Отчёты и снимки находятся
в `outputs/entity-references-277/`.

Frontend-проверки дополнительно покрывают реактивное обновление связей, настройки
представления, смену пользователя и неизменность хешей при изменении метаданных
связей. Всего в итоговых адресных frontend/script-прогонах прошло 119 тестов.
Выполнены TypeScript, production build и проверка семи ресурсов DiceBox.

Общий `go test ./...` имеет прежнее падение
`TestExactUpdateValidationPreservesIdentityAndServerFields`: старое ожидание
статуса `support` расходится с текущей ручной проверкой. То же падение воспроизведено
на отдельной неизменённой копии HEAD; к связям оно не относится. Новые проверки
проходят.

## Восстановление локального PostgreSQL

В исходном каталоге `C:/Users/alexe/AppData/Local/dnd-cards-dev/postgres/data`
операции эксклюзивного создания новых файлов возвращали `File exists` даже для
отсутствующих файлов. Это мешало создавать таблицы и повторно запускать сервер.

После штатной остановки весь кластер скопирован без удаления исходных файлов в
`C:/Projects/dnd_cards/.local-postgres`. Сервер восстановлен на прежнем
порту 5434, все базы доступны; рабочее приложение повторно подключилось.
Исходный `postgresql.conf` содержит `data_directory` с новым путём; оригиналы
конфигурации сохранены в `outputs/entity-references-277/original-postgresql*.conf`.
Для `pg_ctl` следует явно указывать новый каталог через `-D`.

**`.local-postgres` теперь содержит рабочие данные локального сервера и исключён
из Git; его нельзя удалять как временный результат.** Исходный каталог — сохранённая копия
до миграции, новые записи поступают в активный каталог.

Основной локальный backend обновлён на порту 8080; штатный интерфейс на
`http://127.0.0.1:3001` работает с мигрированной рабочей базой. Дополнительно
проверены настоящий список эффектов и связи существующего эффекта на этом адресе.

Для приёмки использовался отдельный интерфейс на порту 3002, копия базы на 5547
и backend на 8082. После проверки эти временные процессы остановлены, тестовые
сущности удалены из копии. Основной интерфейс на 3001 и backend на 8080 работают.
