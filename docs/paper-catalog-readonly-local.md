# Локальный каталог для проверки бумажного листа

`scripts/paper-sheet/start-catalog-readonly.ps1` собирает читаемый QA-entrypoint `catalog-readonly-main.go` вместо `backend/main.go` через Go overlay. Исходный backend не изменяется. Используются текущие каноничные GET-обработчики каталога, без отдельной копии правил фильтрации/сериализации.

Ограничения запуска заданы непосредственно в исходнике:

- HTTP слушает только `127.0.0.1:8080`.
- Подключение только к существующей локальной БД `shop_review_249_20260915` на `127.0.0.1`. По умолчанию порт `5434`; явный `-DatabasePort 5432` выбирает второй разрешённый локальный порт. Имя БД и адрес изменить нельзя; фактический порт проверяется через PostgreSQL перед запуском.
- Из `local-env.json` читаются только локальные PostgreSQL credentials; environment процесса очищается, сохраняется лишь системный путь Windows `SystemRoot`, необходимый для сетевого драйвера. Файлы `.env` не загружаются.
- Каждое соединение получает PostgreSQL `default_transaction_read_only=on` и ограничение времени запроса 5 секунд. Перед запуском проверяются `transaction_read_only`, `default_transaction_read_only`, адрес сервера и имя БД.
- Нет миграций, авторизации, пользовательских/боевых endpoints, worker, фоновых слушателей или конструкторов внешних сервисов. Исходящий HTTP API-процесса выключен.
- Доступны только GET списков/сущностей cards, spells, actions, feats, effects, backgrounds, races, classes, resources, variables, concepts и связанных тегов/изображений. Метаданные тегов всегда доступны как локальное чтение без административных прав. Остальные методы возвращают 405.
- Обработчик изображений умеет отдавать сохранённые изображения и перенаправления из каноничных данных; браузер может отдельно загрузить публичный URL изображения. API-процесс сам внешние изображения не запрашивает.

Проверить подключение без запуска сервера, из корня проекта:

```powershell
./scripts/paper-sheet/start-catalog-readonly.ps1 -CheckOnly
```

Запустить каталог:

```powershell
./scripts/paper-sheet/start-catalog-readonly.ps1
```

Ожидаемое состояние [http://127.0.0.1:8080/api/health](http://127.0.0.1:8080/api/health): `mode: local-read-only-catalog`, оба значения read-only равны `on`, `server_port` совпадает с выбранным портом БД. UI запускается отдельно на [http://127.0.0.1:3000/paper-sheet](http://127.0.0.1:3000/paper-sheet), его API URL — `http://127.0.0.1:8080` либо локальный `/api` proxy Vite на тот же адрес.

На стенде 02.10.2026 актуальный кластер `.local-postgres` уже работает на `5432`, а `5434` закрыт. Для него команды имеют вид:

```powershell
./scripts/paper-sheet/start-catalog-readonly.ps1 -DatabasePort 5432 -CheckOnly
./scripts/paper-sheet/start-catalog-readonly.ps1 -DatabasePort 5432
```

Сервер PostgreSQL запускать заново или переносить не требуется. Существование review-БД и путь актуального кластера подтверждены запросом только на чтение.

Локально проверено 22.09.2026: соединение с указанной БД и оба флага `on`; списки возвращают 882 предмета, 394 заклинания и 18 тегов, отдельные карточки предмета и заклинания читаются. У каталога тегов `can_manage=false`. Пробный `POST /api/cards` с пустым объектом отклонён HTTP 405 до обращения к данным. Сокет подтверждён на `127.0.0.1:8080`.

Повторная HTTP-проверка 02.10.2026 после добавления маршрутов черт и происхождения:

| Раздел | Записей в текущей локальной БД |
| --- | ---: |
| actions | 222 |
| feats | 77 |
| effects | 707 |
| backgrounds | 16 |
| races | 36 |
| classes | 62 |

У всех шести разделов GET списка с `fields=list`, GET первой карточки по UUID, вторая страница и поиск по имени вернули HTTP 200. ID/имя карточки совпали со списком; две проверенные страницы не пересекались. Несуществующий UUID вернул 404. Пробный POST с пустым объектом в каждом разделе вернул 405 до контроллера; `/api/auth/me` отсутствует (404). Health подтвердил `127.0.0.1:5432`, прежнее имя review-БД и оба флага `on`; HTTP-сокет слушает только `127.0.0.1:8080`. База, миграции и конфигурация PostgreSQL не изменялись. Эта проверка выполнена HTTP-запросами, не через браузер.

Это сокращённый сервер для локальной проверки чтения. Создание, изменение, удаление библиотечных сущностей и остальные экраны, которым нужен полный backend, здесь не работают. Сборка использует только уже доступные Go-зависимости (`GOPROXY=off`, `-mod=readonly`); при их отсутствии команда остановится, не скачивая пакеты. Бинарник и overlay находятся в `.tmp/paper-sheet/catalog-readonly`.

## Стенд с сохранением бумажных документов

Редактор `/paper-sheet/:id` использует серверные документы. Для проверки создания, сохранения и загрузки предусмотрен отдельный entrypoint `document-qa-main.go`, который обслуживает только изолированную копию `paper_sheet_20261002_qa` на локальном PostgreSQL. Адрес API — `127.0.0.1:8082`; каталог внутри копии читается отдельным пулом с `transaction_read_only=on`, изменения бумажных документов и локальных аккаунтов разрешены только в копии.

Подготовка новой копии и запуск из корня проекта:

```powershell
./scripts/paper-sheet/prepare-document-qa.ps1 -DatabasePort 5432
./scripts/paper-sheet/start-document-qa.ps1 -DatabasePort 5432 -CheckOnly
./scripts/paper-sheet/start-document-qa.ps1 -DatabasePort 5432
```

Подготовка читает исходную review-БД через `pg_dump`, проверяет свободное место и восстанавливает снимок в новую БД. Существующая копия или файл снимка не заменяются. При повторном запуске готового стенда нужен только `start-document-qa.ps1`. Штатный `backend/main.go`, миграции, `.env`, внешние клиенты и слушатели боя не запускаются; исходящий HTTP отключён. Сессионный JWT-ключ создаётся отдельно в игнорируемой локальной директории и не берётся из продовых настроек.

Для интерфейса на порту 3000 локальная игнорируемая настройка `frontend/.env.development.local` содержит `VITE_API_URL=http://127.0.0.1:8082`. Она действует только в режиме разработки. Vite применяет изменение этой настройки автоматически; сборка для публикации сохраняет обычный API того же origin.

Проверено 02.10.2026: POST → GET → PUT → GET нового анонимного документа сохранил выбранные ID происхождения, снимок способностей и ручной текст; ревизия увеличилась с 1 до 2. Отдельный старый документ версии 1 без новых полей сохранил произвольные вид, класс и заметку. Все записи созданы только в QA-копии. Чтение настоящего каталога и каноничная сборка особенностей проверены для двух разных наборов вида/подвида, класса/подкласса и предыстории на уровнях 1 и 3. Браузерная визуальная проверка в этой сессии была недоступна из-за политики встроенного браузера.
