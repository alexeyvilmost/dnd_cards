# Основной и расширенный наборы

Единая точка входа из корня: `node scripts/testing/run.mjs --suite core`. Она не читает рабочий `.env`; для интеграции создаёт собственные PostgreSQL, API, rules-worker и production preview. Нужны установленные зависимости frontend, Node24, Go1.25 и PostgreSQL17 binaries. Явные пути: `--go <executable>`, `--pg-bin <directory>`. Lifecycle и версии fixtures описаны в `scripts/testing/README.md`.

| Команда | Состав |
| --- | --- |
| `--suite core` | Обязательные контракты безопасности и выбранных компонентов, сборка, реальные PostgreSQL-транзакции, API/worker и браузерные сценарии четырёх главных разделов |
| `--suite extended` | Core и все остальные текущие локальные регрессии; исторические случаи имеют явные исключения в манифесте |
| `--suite legacy-manual --select entity-certificates` | Только явно выбранная старая диагностическая матрица; не меняет ручной статус проверки сущностей |
| `--plan-only` | Проверяет манифест и выводит выбор, не запускает проверки и не объявляет PASS |

Linux-профиль `--race` включает Go race detector во всех обязательных Go-проверках, включая shared-stack gates. Нужен C toolchain; отсутствие поддержки завершает запрос ошибкой, не skip. CI добавляет эту опцию к extended. На текущем Windows-стенде race не выполнен; native concurrency checks и remote Linux race — разные доказательства.

`frontend` предоставляет `npm test`, `npm run test:core`, `npm run test:extended`, `npm run test:legacy-manual -- --select <id>`. `scripts/release/quick-gate.ps1` и `scripts/run_tests.sh/.bat` вызывают тот же runner. Старый `-Full` означает extended; старый `-LegacyEntityTests` без точного `-LegacySuite` отклоняется. Старые Python HTTP tests изолированы; их проверки нельзя считать настоящим browser E2E.

Выбор использует `scripts/release/component-dependencies.json`. Без `--base` выбираются все компоненты. `--base <commit>` учитывает изменения относительно этого commit и локальный staged/unstaged/untracked код. Неизвестный путь включает весь core; rename учитывает обе стороны. Изменение реализации достаточно для включения контракта, менять test file для этого не требуется. Только документация запускает security/manifest checks. Явный extended всегда выбирает полный набор, даже при docs-only diff.

Отчёт `outputs/testing/suites/<id>/report.json` содержит SHA, хэш tracked diff, хэши изменённых исходников и lockfiles, fixture/artifact identity, версии Node/Go, причины выбора, длительности и реальные результаты. `test-catalog.json` перечисляет владельца, runner, tier, контракт и исторические случаи. Файлы с секретами и полный diff в отчёт не записываются. Compile-only Go явно отмечен отдельно; он не считается выполнением тестов. Go root PASS не скрывает skipped subtest. Vitest/Node с 0 тестов или skip завершают набор ошибкой.

Стенд строит UI/worker один раз на прогон. `--reuse-ui-build` разрешён только локально как явно ослабленная диагностика; в CI запрещён. Тайминги при параллельных локальных сборках диагностические. Для release acceptance используйте свежую сборку. `source-snapshot.json` сохраняет hashes исходников, данных, media и конфигурации проверяемых компонентов; финальный gate отклоняет результат, если во время запуска изменился HEAD, добавился, удалился или изменился один из этих файлов. Generated outputs и секретные `.env` исключены. Изменение текста отчётов в `docs` не требует повторной проверки кода.

Extended включает обязательные `extended_gates` из того же манифеста: серверная экипировка и ресурсы, варианты инициативы для групп 1/2/6, сводки и страницы 11 каталогов, браузерный повтор потерянного ответа и PWA offline shell. Эти gates используют уже созданный owned stack; для них только в extended включены flags оборудования/инициативы и наблюдаемость. Замеры производительности по 30 повторов запускаются отдельно: функциональный gate использует один повтор и не объявляет SLA. Core сохраняет обычные выключенные flags новых серверных режимов.

Исторический corpus выполняется сохранённым старым executable artifact и текущим reader. Старые hashes/сертификаты не перезаписываются. Настоящие snapshot-only случаи перечислены по точным именам и причинам; имя папки, возраст теста или слово `live` не являются основанием исключения. Для общей финальной проверки остановите редактирование исходников на время прогона: проверка release fingerprint намеренно обнаруживает изменение кода между созданием evidence и его проверкой.

Для всех 15 типов `rules-core.PendingResolution` есть отдельный frozen corpus из 71 принятого перехода: JSON reload, точный RNG/ID/result, duplicate rejection и два новых Node-процесса. Это текущие синтетические continuations; они дополняют исторический worker corpus и API-квитанции. Writer запускается явно и пишет только новую версию; обычный тест ожидаемые результаты не создаёт.

Поддерживаемые upgrade297/298/299→300 выполняются на трёх отдельных owned PostgreSQL базах с полной схемой и непустыми связанными данными. Проверяются реальные startup migrations, повторный запуск без изменений, исходные FK/индексы/функции/триггеры, история и ручные статусы. Import baseline001–297 явно отмечен и не считается исполнением полной исторической цепочки. На Windows один проверяемый test binary сохраняется в отчёте и запускается через Go test2json: ошибки exit/skips по-прежнему запрещены.

Тестовые сценарии повторно используют полученный через настоящий API login в памяти одного процесса. Кеш привязан к owned run, origin, роли и credentials; каждый доступ проверяет readiness, ошибка не кешируется и не повторяется автоматически. Проверки самого входа по-прежнему выполняют реальные запросы. Это предотвращает исчерпание лимита входов множеством fixtures, не меняя ограничения рабочего сервиса.

`local-browser-flows` запускает все объявленные `e2e-local` файлы через настоящую серверную цепочку на том же стеке. Extended отдельно выполняет прежний UI-fixture слой: desktop/mobile на production build, dev-only 3D на ограниченном Vite server без `.env`. У этого слоя собственный origin без API upstream; allowlist proxy блокирует внешнюю сеть и чужие локальные порты, включая запросы service worker. Браузерный JSON отчёт с пропуском, повтором, отсутствующим файлом или 0 тестов не проходит gate. Traces/video выключены, поскольку могут сохранять credentials; локальные screenshots допустимы. Диагностика слоя: `node scripts/testing/check-ui-fixtures.mjs` или `--battle3d`; только локальная опция `--reuse-ui-build` явно разрешает предыдущую сборку.

Go differential каталога и кеша требует API-created party fixtures и реального worker; `dedicated_go_routes` направляет эти случаи в обязательные gates полного стека. 35 точных исторических Go cases требуют каталога/preimage/специального snapshot и перечислены в `legacy_manual.snapshot-migrations.go_cases`. Статические проверки в тех же файлах остаются в extended. Подстановка случайной БД в эти случаи запрещена. Integration schema baseline297 не доказывает успешную свежую историческую цепочку миграций. Состояние финальных прогонов и оставшиеся ограничения перечислены в `docs/audits/2026-10-04/execution/TEST-03.md` и `TEST-05.md`; подключение слоя само по себе не считается успешной проверкой.

CI вызывает этот же runner с event base SHA и публикует только проверочные JSON-отчёты. Pull request выбирает core или extended по изменённым компонентам. Каждый push в main запускает extended: между последней выкаткой и последним push могут накопиться изменения backend/движка, даже если последний commit касается только UI. Это обеспечивает проверку точного кандидата для автоматической выкатки. Ручной диагностический запуск сохраняет выбранный набор, но core не разрешает выпуск критичных изменений. CI требует чистый checkout до начала и неизменные исходники до конца прогона.

Новый кластер создаётся обычным runner-пользователем, не от root. Для PostgreSQL17 используются [официальные пакеты PGDG](https://www.postgresql.org/download/linux/ubuntu/); структура workflow сверена с [документацией GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax). Workflow проверен локально как YAML и набор контрактов; удалённого запуска в этом поручении не было.
