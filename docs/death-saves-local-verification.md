# Спасброски от смерти в бою — 17.09.2026

## Механика

- Общие функции листа и боя перенесены в `engine/deathSaves.ts`; прежний импорт `character/death.ts` сохранён как реэкспорт.
- Начало хода фиксирует, что персонаж уже имел 0 HP. Падение во время собственного хода не создаёт досрочный спасбросок.
- Авторитетная команда `DeathSavingThrow` использует общий расчёт, ресурсную модель и журнал. Добавлено сохранение `deathSaves` в каноническом runtime patch (прежде поле не попадало в него).
- Результат и случайная последовательность сохраняются до подтверждения. Общие data-driven действия влияния доступны в том же диалоге. Подтверждение воспроизводит сохранённую последовательность без повторного расхода энтропии.
- UI использует `CombatPresentationDialog` и общий к20, со счётчиками 0–3. Натуральные 1/20 получают общие критические анимации. Подтверждение не закрывает диалог и не вращает ту же кость повторно.
- Натуральная 1 — два провала; 20 — восстановление 1 HP, сброс счётчиков и возможность продолжить текущий ход. Три успеха — стабилизация, три провала — смерть. См. [SRD 5.2, Damage and Healing](https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.pdf).
- Остающийся без сознания персонаж после закрытия результата передаёт ход дальше. Стабилизированные и погибшие не бросают к20. Поражение не объявляется только из-за 0 HP у всей группы, пока остаются нестабилизированные живые персонажи со спасбросками.

## Проверка

- Тесты: натуральные 1, 9, 10, 19, 20, оба управляемых персонажа, третьи успех/провал, стабильность/смерть, повторное подтверждение, JSON-перезагрузка, разные фазы хода, вдохновение и сохранение стоимости, каноническая граница импортов.
- UI-тесты: счётчики, критические анимации, сохранение экземпляра окна и кубика при подтверждении.
- На изолированной копии пользовательского боя (ревизия 141, начало хода Линейного бойца с 0 HP) проверены подготовка, подтверждение и передача хода лучнице. Исходные HP, счётчики и случайная последовательность реального боя при проверке не менялись.
- Лечение двумя разными декларациями также проверено: сбрасываются счётчики и стабилизация, чтобы следующее падение начинало новый эпизод спасбросков.
- Обновление локального боя выполняется явной записью `local_rules_upgrade` через `scripts/roguelike/area-cover-local-upgrade.mjs --death-saves --apply`. Только версия, capability и маркер уже наступившего начала хода; без переброса истории и без изменения HP/счётчиков.
