# Аудит механик каталога: миграция 278

Каноничные входные файлы находятся в `backend/migrations/data/catalog-audit-20260929/*.json` (`items`, `feats`, `spells`, `item-influences`) и входят в Go-бинарник через `go:embed`. Скрипты подготовки должны писать туда. Migration 277 предварительно добавляет восьмой ручной статус.

Каждый manifest содержит `schema_version: 1`, уникальный `audit_id`, общий `source_snapshot_sha256` (64 шестнадцатеричных символа в нижнем регистре), `entities` и необязательный `guards`. Строка сущности содержит `entity_type`, UUID `id`, `card_number`, читаемое `name`, `description_sha256`, `preimage`, `patch`, `review`. Поддерживаемые типы: `card`, `feat`, `spell`, `action`, `effect`, `resource`. У ресурса `card_number` обозначает его `resource_id`.

`description_sha256` — SHA256 от UTF-8 результата `JSON.stringify([description ?? null, detailed_description ?? null])`. Для новой сущности используется пара из `patch`. `name` помогает читать отчёт; для проверки текущего имени оно должно также входить в `preimage`.

`preimage` перечисляет проверяемые поля БД, включая каждое поле из `patch`. Значения сравниваются через JSONB equality: порядок ключей объекта не важен, порядок массива и тип значения важны. Значение TEXT-поля с JSON внутри остаётся JSON-строкой как в SQL-снимке; декодировать его в массив/объект нельзя. `updated_at`, изображения, источник и прочие посторонние метаданные существующей сущности не сравниваются и не меняются. `deleted_at` допускается в guard; сама сущность обязательно должна быть активной.

`preimage: null` означает вставку новой связанной сущности. Проверяется отсутствие и UUID, и номера, включая удалённые строки. `patch` содержит обязательные поля; `id`, номер и `name` берутся из заголовка либо должны точно ему соответствовать. Остальные пропущенные поля получают обычные DB defaults. `deleted_at`, если задан, должен быть `null`.

`review` содержит `status`, `summary`, `implemented`, `tested`, `limitations`, `evidence`. Миграция запрещает `verified` и `partial_narrative_verified`. Статус выбирается явно автором аудита, тесты не повышают его автоматически. После механического изменения отдельный UPDATE сохраняет статус, `note = summary`, ограничения, время, audit ID и подробности проверки. Неизвестные поля прежнего support сохраняются; прежние certification hashes, evidence и lock удаляются из текущего support, но точный оригинал архивируется.

`guards` содержит записи того же формата идентичности и `preimage`, без `patch` и `review`. Это проверки общих зависимостей; их данные и статусы не меняются. Guard может ссылаться на сущность, изменяемую другим manifest, но изменять одну сущность двумя записями запрещено.

Вся миграция атомарна. Она блокирует затрагиваемые таблицы для записи (обычные SELECT продолжаются), затем строки, проверяет все описания и preimages и лишь после этого записывает каталог. Такой порядок также защищает отсутствие новых UUID/номеров. Конфликт, недопустимая колонка, неправильный тип или ошибка ограничения откатывает весь пакет. Миграция не обращается к истории боёв.

`catalog_mechanics_278_archive` хранит исходные изменяемые поля, полный прежний support, применённый patch и review. `catalog_mechanics_278_transition` закрепляет hash входных manifests. Повтор с теми же входами ничего не перезаписывает, включая более поздние ручные правки; изменение уже применённого manifest отклоняется. Автоматический откат запрещён: нужен отдельно проверенный обратный manifest.

Локальная проверка: `CONTENT_MIGRATION_TEST_DSN=... go test ./migrations -run '^TestCatalogAudit278' -count=1`. Тесты создают изолированные схемы и проверяют разные типы сущностей, SQL rollback, конкурентную правку, повторный запуск, сохранность истории/метаданных, вставки и конфликты идентичности. Следующий уровень проверки — применение к отдельной восстановленной копии production-снимка, сравнение полного каталога с разрешёнными изменениями и сценарии общего исполнителя/UI для затронутых операций.

## Заклинания от предметов

Активный по обычному `itemGate` предмет выдаёт существующее заклинание через `grant_spell` со стабильной ссылкой `value`, характеристикой `ability` и явно заданным доступом `label`. Лист и боевой сборщик загружают каноничную сущность заклинания; снятие предмета убирает выдаваемый доступ, в том числе при позднем завершении запроса.

`freeuse: {at_will: true}` означает применение без ячейки и без ограниченного пула. В каноничном доступе это существующий `innate` без payment resource; стоимость действия и прочие затраты сохраняются. Ограниченный вариант остаётся `freeuse: {count: 2, recharge: "long_rest"}`; повторная загрузка не восстанавливает потраченные применения. Скомпилированное действие предмета содержит `requires_item_source`: общий исполнитель повторно проверяет экипировку/инвентарь и настройку на предмет до оплаты, поэтому старая запись действия не даёт использовать снятый предмет. Статус проверки сущности на доступ не влияет.

## Предметные влияния и настройка

Все JSON из каталога `backend/migrations/data/catalog-audit-20260929` включаются миграцией в отсортированном порядке. Дополнительный `item-influences.json` создаёт 14 обычных действий; изменения 17 исходных предметов добавляются основным авторским сборщиком из `scripts/content/data/item-influences-20260929.json`. UUID/номера предметов существуют только в данных и тестовых сценариях.

`grant_action` предоставляет действие с `requires_item_source`, явной стоимостью и `roll_influence`. Общий контракт различает `before_roll` и `after_roll_before_outcome`, допускает переброс сохранённого к20, преимущество/помеху, успех и `critical_on_hit`. Последняя операция не превращает промах в попадание; `penalty_dice` оставляет в журнале отдельные отрицательные кости и источник. Противоположные источники преимущества сохраняются отдельными флагами, поэтому дополнительное преимущество не отменяет уже существующую помеху при наличии обоих типов.

Выбор до броска и удержанный результат сохраняются в обычном боевом продолжении. Перед оплатой повторно проверяются актуальный предмет и стоимость. При продолжении переиспользуется журнал случайных чисел; повтор уже принятой команды не выполняет бросок снова. `affects: any` допускает реакцию владельца на чужой к20, `once_per_turn` связан с фактическим ходом боя. `d20_interrupt.target_self` ограничивает реакцию атаками против владельца, а `once_per_encounter` хранит расход в снимке данного боя.

Пассивный `attunement_capacity: {amount: N}` меняет базовые три места только после обычного предметного gate. Лист, бумажный лист и серверная проверка лагеря используют эти данные. Потеря источника ёмкости не удаляет прежние выборы; новые настройки сверх доступной ёмкости запрещены сервером.

Ограничения записаны в review каждой сущности: откат времени и не-к20 перебросы, выбор до инициативы/спасброска смерти, независимая календарная граница дня и постоянная потеря места настройки пока не реализованы. Для рискованного преимущества автоматический штраф требует известного провала и заканчивается долгим отдыхом. Эти записи не получают полный verified.
