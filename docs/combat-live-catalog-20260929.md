# Запуск боя из актуального каталога

## Причина отказа HTTP 422

Новый бой собирал действия из текущих данных, затем сравнивал их с замороженным
сертификатом micro-MVP. В воспроизведённом забеге первым различием оказался
`action.spell.entityId`: канонический компилятор уже сохраняет идентификатор
заклинания, а прежний сертификат его не содержал. Поэтому корректная команда
инициализации отклонялась до применения изменений.

## Исправление

Новые сессии используют канонически собранные действия и права участников.
Сессия сохраняет собственный каталог и хеш его состава, назначений действий и
доступа к заклинаниям. Совместимость правил проверяется отдельно от различий
между личными каталогами персонажей. При чтении продолжения проверяются версия
правил, хеш и права владельцев действий.

Общие оружейные действия сохраняют исходную механику до привязки экипировки.
Дальность, режим атаки и стоимость боеприпасов вычисляются для действующего
персонажа. Привязанный результат сверяется с его каноническим действием.

Старые незавершённые решения остаются под прежним сертификатом; их история и
артефакты не переписываются. Завершённый старый снимок больше не мешает собрать
следующее действие из актуальных данных. То же правило применяется на обычном
листе персонажа.

## Проверка

Регрессии покрывают два разных заклинания с актуальной идентичностью,
повреждение сохранённого каталога, старое незавершённое решение, разные профили
безоружного удара и разное оружие участников в обоих порядках добавления.
Отдельно воспроизводится исходная инициализация забега на локальном снимке БД
через Go backend и HTTP rules worker. Локальные дампы и запросы в Git не входят.

Для релиза также изменён контекст Docker-сборки frontend: общий каталог
анимаций берётся из `backend/animationpresentation/catalog.json`, с сохранением
единственного источника метаданных.
